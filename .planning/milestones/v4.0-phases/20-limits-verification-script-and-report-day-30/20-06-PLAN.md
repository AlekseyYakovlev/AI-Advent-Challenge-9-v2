<objective>
Prove the phase end to end on a running app without touching the user's instance: start an
isolated copy with low demo limits and a deliberately slow stub model, check the supervisor
start-up, the guarded route and the limits log line, run the real `verify_service.py` against
it as a separate process, and drive a headless browser through the three UI states.

Purpose: unit tests in plans 20-01..20-05 use in-process clients and a stub server; this plan
is the only place where the real two-process app, real sockets, a real cross-origin browser
and the real script meet before the user's live run (plan 20-08). It gives the user's run a
rehearsal, so that the Mac run is not the first time the script meets the server.
Output: `scripts/e2e_limits_playwright.py` and the recorded result of running it.

Project rule for checks that need a running app (user feedback, see the Phase 18 plan 18-07
and the existing `scripts/e2e_*_playwright.py`): they run on an isolated copy on ports
18000/18001 with a scratch database; the app on 8000/8001 is never stopped, restarted or
probed, and only processes started by the script are stopped.

This is a rehearsal on one machine through loopback. It is not the live run from a second LAN
machine (VER-04); its results are never written into `eval_out/day30/` and are never presented
as the LAN run.
</objective>

| T-20-42 | Tampering | the check altering the repository `.env`, `app.db` or the firewall | high | mitigate | The copy has its own `.env` and database (`prov.prepare_copy`, `prov.seed_scratch_user` refuses the repository database); loopback bind, so no firewall prompt |
| T-20-43 | Repudiation | rehearsal results mistaken for the live LAN run | high | mitigate | Output stays in the scratch directory; the script never writes under `eval_out/`; acceptance check on `git status --porcelain eval_out`; the report (plan 20-08) labels it as a loopback rehearsal |
| T-20-44 | Information disclosure | the scratch API key on a command line or in kept files | medium | mitigate | The key reaches the subprocess only through `AIA_API_KEY`; V1 asserts the key is absent from the captured output and both result files; the scratch database is discarded |
