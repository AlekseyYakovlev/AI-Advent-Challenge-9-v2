<!-- Facts to document (fixed by plans 19-01, 19-02, 19-04; confirm each against the source before writing) -->

Auth: `Authorization: Bearer aia_<43 chars>`; header present -> the key alone decides (no cookie fallback); other schemes are ignored; invalid, empty or revoked key -> 401 `Invalid or revoked API key` with `WWW-Authenticate: Bearer`. Cookie-only routes (403 for a valid key): `POST/GET /api/v1/api-keys`, `DELETE /api/v1/api-keys/{key_id}`, `POST /api/v1/auth/users`, `POST /api/v1/auth/logout`. WebSocket `/ws/chat/{chat_id}` and `/ws/events`: cookie only.

Key routes: `POST /api/v1/api-keys` `{"name"}` -> 201 `{"id","name","key","key_prefix","created_at","last_used_at"}` (409 at 20 keys, 422 bad name); `GET /api/v1/api-keys` -> list without `key`; `DELETE /api/v1/api-keys/{key_id}` -> 204 / 404. Storage: sha256 hash and 8-character prefix only; `last_used_at` refreshed at most once per 60 seconds; no expiry; revoke deletes the row.

HTTP chat: `POST /api/v1/chats/{chat_id}/messages`; body `content`, `model`, optional `provider_id`, optional `kb_id` (id | null | omitted); 200 body `chat_id`, `user_message_id`, `assistant_message_id`, `content`, `model`, `provider_id`, `stats`, `tool_calls`, `memory_writes`, `task_writes`, `invariant_conflict`, `rag`; error body `detail`, `code`, `user_message_kept`, optional `suggested_strategy`.
Status table: 200; 401; 403 (foreign Origin); 404 (chat or KB, default shape); 409 `CHAT_BUSY`; 413 `CONTEXT_OVERFLOW` + `suggested_strategy: "sliding"`; 415; 422 (validation, KB not ready); 500 `RAG_GATED_FAILED` / `INTERNAL_ERROR`; 502 `LLM_ERROR`; 503 `LM_STUDIO_UNAVAILABLE` / `LLM_UNREACHABLE` / `PROVIDER_UNAVAILABLE`.
Event: `{"type": "chat_updated", "chat_id"}` on `/ws/events` after a successful HTTP turn.
WebSocket changes from plan 19-02: failed turn restores `current_leaf_message_id`; `LLM_ERROR` frame gains `cause` (`unreachable` | `timeout` | `upstream`) and `provider_kind`.

Address: external clients call the Agent directly at `http://<host>:<AGENT_PORT>` (default 8001), not the UI port; from another machine the app must run in LAN mode (`BIND_HOST=0.0.0.0`, Phase 18). A request without an `Origin` header passes the Origin check, which is why curl works.

Existing doc anchors (verified 2026-10-12): docs/API_SPEC.md `## WebSocket Messages` (line 72), `### WS /ws/events` (line 256), `## Network (Day 30)` (line 729), `## Environment Settings` (line 749); docs/TESTING_GUIDE.md `## LAN exposure (Day 30)` (line 414, last section); docs/ARCHITECTURE.md `## Network exposure and the Origin rule` (line 9); docs/USER_GUIDE.md `## LAN mode` (line 228), `## Tips` (line 292).
Request models to check for the scenario: `LoginRequest` (`username`, `password`), `McpServerUpdate` (`enabled`), the body model of `POST /api/v1/lm-studio/load-model` in agent/main.py (line ~1347) and of `POST /api/v1/chats` (`title`).
