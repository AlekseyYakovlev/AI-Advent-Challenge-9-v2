Create `agent/tools.py` with module docstring "Tool-call registry and strictly sequential dispatcher." and `logger = get_logger(__name__)`. Contents:

1. `ToolHandler = Callable[[AsyncSession, int, int, dict[str, Any]], Awaitable[dict[str, Any]]]` — the parameters are `(session, user_id, chat_id, args)`.
2. `TOOL_REGISTRY: dict[str, ToolHandler] = {}` and `TOOL_SCHEMAS: dict[str, type[BaseModel]] = {}` and `TOOL_DESCRIPTIONS: dict[str, str] = {}`.
3. `def register_tool(name: str, args_model: type[BaseModel], description: str) -> Callable[[ToolHandler], ToolHandler]` — decorator that records the handler, its Pydantic argument model, and its description under `name`.
4. `def build_tool_schemas() -> list[dict[str, Any]]` — for each registered name, emit `{"type": "function", "function": {"name": name, "description": TOOL_DESCRIPTIONS[name], "parameters": schema}}` where `schema = args_model.model_json_schema()` with the top-level `"title"` key removed (`schema.pop("title", None)`) and any per-property `"title"` keys removed too, so the model sees a clean JSON Schema. Do not hand-write JSON schema dicts.
5. `async def dispatch_tool_calls(session: AsyncSession, user_id: int, chat_id: int, tool_calls: list[dict[str, Any]]) -> list[dict[str, Any]]` — iterate with a plain `for` loop in the order received. NEVER `asyncio.gather`, never `asyncio.create_task`, never open a new session or acquire a lock: the caller already holds the per-chat lock and the open session (STATE.md hard constraint; a later call in a turn may depend on an earlier one). For each call:
   - read `name = call["function"]["name"]` and parse `call["function"]["arguments"]` with `json.loads` inside `try/except json.JSONDecodeError` (never a bare `except:`); on failure append `{"tool_call_id": call.get("id"), "name": name, "ok": False, "content": json.dumps({"error": "malformed arguments"}), "write": None}` and `continue`.
   - if `name not in TOOL_REGISTRY`, append an equivalent entry with `{"error": f"unknown tool {name}"}` and `continue`.
   - validate the parsed args with the registered Pydantic model inside `try/except ValidationError`; on failure append a structured error entry with the validation message and `continue`.
   - strip and ignore any `chat_id` / `user_id` keys present in the LLM-supplied arguments, logging `logger.warning("tool_args_scope_override_ignored", tool=name, tool_call_id=...)`. Scope always comes from the dispatcher's own trusted parameters.
   - `result = await TOOL_REGISTRY[name](session, user_id, chat_id, validated_args)`; append `{"tool_call_id": call.get("id"), "name": name, "ok": True, "content": json.dumps(result), "write": {"id": result.get("id"), "key": result.get("key"), "layer": result.get("layer")}}`.
   - log every dispatch with `logger.info("tool_call_dispatched", tool=name, tool_call_id=call.get("id"), chat_id=chat_id)` — per 02-RESEARCH.md Pitfall 1, every memory write must be traceable to a triggering `tool_call.id`, so a write without one is provably a bug.
6. Two handlers registered via the decorator:
   - `save_working_memory(session, user_id, chat_id, args)` → `row = await memory.save_working_memory(session, user_id, chat_id, args["key"], args["content"])`, return `{"status": "saved", "layer": "working", "key": row.key, "id": row.id}`.
   - `save_long_term_memory(session, user_id, chat_id, args)` → `row = await memory.save_long_term_memory(session, user_id, args["key"], args["content"])`, return `{"status": "saved", "layer": "long_term", "key": row.key, "id": row.id}`. Note it deliberately ignores `chat_id`: long-term memory is user-scoped and cross-chat (D-02).
   Tool descriptions must make the layer distinction explicit to the model, e.g. working = "temporary scratchpad for the CURRENT chat's task data; overwritten per key", long-term = "durable fact/decision/preference about the user that should persist across ALL chats".

`agent/tools.py` must contain zero `asyncio.gather`, zero `asyncio.create_task`, zero `asyncio.sleep`, and zero `async_session_factory` usage.
