# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hard project constraint: vanilla JS + CDN Tailwind only, no bundler, no npm packages (`CLAUDE.md` Hard Constraints; `ui/static/index.html` loads Tailwind from `cdn.tailwindcss.com`). shadcn requires a React/Next/Vite build pipeline and is not applicable to this stack — gate skipped, not just declined. |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind utility classes, mirroring the existing Memory/Profile/Tasks sidebar panels in `ui/static/index.html` and `ui/static/app.js` |
| Icon library | none — Unicode/emoji glyphs only, matching existing usage (👥 users, ⚙️ settings, ⏸ paused, ⚠️ warning). New fold/unfold toggle (D-11) uses `▾` (expanded) / `▸` (collapsed) text glyphs, not an icon font |
| Font | system default sans stack (no `@font-face` override anywhere in the codebase; Tailwind CDN default) |

This phase does not introduce a design system — it extends the one already implemented across Phases 2-4 (Memory/Profile/Tasks panels). All new Invariants UI and the D-11 fold/unfold retrofit must reuse the tokens below, which are extracted from the current `ui/static/index.html` and `ui/static/app.js`, not invented fresh.

## Spacing Scale

Declared values (Tailwind's default 4px-step scale, as already used throughout `ui/static/`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`p-1`, `px-1`, `gap-1`) | Icon gaps, badge padding, tight inline chips (state badges, ⏸ marker) |
| sm | 8px (`p-2`, `gap-2`, `space-y-2`) | Compact element spacing (task cards, button groups) |
| md | 12px (`p-3`) | Panel padding (existing convention: `#memory-panel`, `#profile-panel`, `#task-panel` all use `p-3`) |
| lg | 16px (`p-4`, `px-4 py-2`) | Section padding, sidebar header/footer, standard button padding |
| xl | 20px (`px-5 py-4`) | Modal header/body padding (existing convention: settings modal, add-user modal) |

Exceptions: this project's existing spacing scale is Tailwind's native 4px-step scale (4/8/12/16/20/24...), not the canonical 8-point-only scale (4/8/16/24/32/48/64) — `p-3` (12px) and `px-5` (20px) are already load-bearing conventions from Phases 1-4 (panel padding and modal padding respectively). The new Invariants tab and the D-11 fold/unfold retrofit MUST match these existing values exactly (12px panel padding, 8px internal item spacing, 4px badge/chip padding) rather than reintroducing a stricter 8-point-only scale that would visually mismatch the three panels it sits beside.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / meta | 12px (`text-xs`) | 400 (regular) | 1.5 (Tailwind default `leading-normal`) |
| Body / buttons / inputs | 14px (`text-sm`) | 400 regular (body text), 500 medium (buttons only — existing convention on every `<button>` in `index.html`) | 1.5 |
| Panel heading | 16px (default/`text-base`, unset by existing `<h3>` panel titles) | 600 (semibold) | 1.2 |
| Page/tab heading | 18px (`text-lg`) | 600 (semibold) | 1.2 |

No Display size exists or is needed — the largest text in this app is the 18px chat title (`#chat-title`). The Invariants tab header follows the same 16px-semibold pattern as the existing Memory/Profile/Tasks `<h3>` panel titles (e.g. `<h3 class="text-slate-300 font-semibold mb-2">Память</h3>`).

Weight note: the codebase already carries 3 weights (400 regular, 500 medium on buttons, 600 semibold on headings/labels/counts/badges) — this is a pre-existing, established exception, not one introduced by this phase. New Invariants elements must follow the same split: buttons → `font-medium`, headings/counts/badges/state chips → `font-semibold`, everything else → default regular weight. Do not introduce a 4th weight.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-slate-950` | Page canvas, chat message area background, `<body>` |
| Secondary (30%) | `bg-slate-900` (sidebar, header), `bg-slate-800` (cards, inputs, panel item rows), `border-slate-700`/`border-slate-800` | Sidebar, header bar, all panel item backgrounds (memory rows, task cards, invariant rows), modals, inputs/textareas/selects |
| Accent (10%) | `bg-indigo-600` / hover `bg-indigo-500`, `focus:ring-indigo-500`, `accent-indigo-500` | Reserved for: primary CTA buttons only (Новый чат, Сохранить профиль, Сохранить/Создать in modals, Продолжить task action, and the new "Добавить инвариант" / "Сохранить инвариант" buttons), input focus rings, range-slider thumbs, and the stats usage bar fill below 75%. Not used for the fold/unfold toggle, not used for badges/counts, not used for the overrides dropdown chrome. |
| Destructive | `bg-red-700` hover `bg-red-600` (buttons: Отменить task, delete chat, delete invariant); `text-red-400` (cancelled state); `bg-red-900/90` + `border-red-700` (error toasts/banners) | Cancel/delete actions and error states only |
| Conflict/attention (secondary semantic, reused from existing `validation` task-state color) | `text-amber-400` (badge text/icon), `bg-amber-900/50` + `border-amber-700` (inline chat banner) | Reserved exclusively for INV-04 conflict signaling: the Invariants-tab conflict-count badge and the inline chat-stream conflict banner. Accent reserved for: primary CTA buttons, input/textarea focus rings, range-slider accent color, and the usage bar. Never used for status/semantic signaling (that's amber/red/emerald's job) and never used for the fold/unfold chevron.

## Interaction Notes (phase-specific, beyond template defaults)

- **Fold/unfold (D-11):** Every sidebar tab except "Chats" (Память, Профиль, Задачи, and the new Инварианты) defaults to collapsed (header-only). Each header gets a toggle button using the `▸`/`▾` glyph pair, right-aligned in the header row, styled `text-slate-400 hover:text-white` (matching existing header icon-button treatment, e.g. `#btn-users`/`#btn-settings`). This is genuinely new shared UI with no prior precedent — implement once as a shared toggle helper and apply to all four panel headers, not four separate implementations. Fold state does not need to persist across reloads (per CONTEXT.md, explicitly low-stakes/unspecified) — reset to collapsed on every page load is an acceptable default.
- **Conflict surfacing is dual per D-12:** the inline chat banner (amber, appears directly under the flagged assistant message) and the Invariants-tab badge (amber count) must both render from the same conflict record — no separate/divergent copy between the two surfaces.
- **Overrides dropdown (D-05):** populated from the global invariants list, keyed by `id`, labeled by `title` (this is why D-01's title field is mandatory) — a `<select>` matching the existing `#model-select`/`#settings-strategy` styling (`rounded-lg bg-slate-800 border border-slate-700 px-3 py-1.5 text-sm`).
- **CRUD forms (D-04):** add/edit invariant forms (both global and per-chat) reuse the existing textarea/input styling from the Profile panel form (`w-full resize-none rounded-lg bg-slate-800 border border-slate-700 px-3 py-2 text-sm focus:outline-none focus:ring-2 focus:ring-indigo-500`) — two fields per CONTEXT.md D-01 (title as a single-line `<input>`, rule text as a `<textarea>`).
