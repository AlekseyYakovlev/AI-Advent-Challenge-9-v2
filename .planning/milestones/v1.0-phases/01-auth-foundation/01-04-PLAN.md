</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser WS handshake (`:8000` page) → Agent `WS /ws/chat/{chat_id}` (`:8001`) | The cookie arrives automatically on the handshake; this is the only moment authentication is checked. |
| Any local process → Agent WebSocket | The port is open on localhost; the origin check alone never proved identity. |
| Open socket → chat message tree | Once accepted, every message on this socket acts as the user validated at accept time. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-24 | Spoofing | `ws_chat` accepting an unauthenticated handshake | mitigate | **HIGH.** `get_current_user_ws` is called before `accept()`; a missing/invalid/expired cookie closes with 1008. Asserted by three rejection tests. |
| T-01-25 | Information Disclosure | IDOR over WebSocket — a logged-in user opening another user's `chat_id` and reading/appending to that chat's tree | mitigate | **HIGH.** `_user_owns_chat` compares `chat.user_id` to the authenticated user before `accept()`. NULL owner returns False. Asserted by the wrong-owner test. |
| T-01-26 | Information Disclosure | Distinguishable close reasons revealing whether a chat id exists or belongs to someone else | mitigate | Both failure paths close with the identical `code=1008, reason="Unauthorized"`; only the server-side structlog line distinguishes them. |
| T-01-27 | Information Disclosure | Accepting the socket first and closing afterwards (leaks handshake success, and an accepted socket can already receive frames) | mitigate | The gate is placed strictly before `await websocket.accept()`, enforced by a source-order acceptance check, mirroring the existing `_validate_origin` precedent. |
| T-01-28 | Elevation of Privilege | A session revoked by logout staying usable on an already-open socket until it disconnects | accept | Direct consequence of D-10 (validate once at accept). The window is bounded by the socket's 300s idle timeout and by the browser navigating away on logout. Re-validating per message was explicitly rejected by the user; revisit only if D-10 is revisited. |
| T-01-29 | Denial of Service | A rejected handshake triggering the client's exponential reconnect loop and hammering the Agent | mitigate | `ui/static/app.js::STOP_RECONNECT_CODES` already contains 1008, so the client stops reconnecting; Task 2 verifies the constant is intact rather than assuming it. |
</threat_model>
