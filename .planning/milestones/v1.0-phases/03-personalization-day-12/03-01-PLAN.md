<objective>
Build the complete backend vertical for user personalization: a `Profile` row per user, a UI-callable REST surface to read and write it, and unconditional injection of those preferences into every system prompt the agent assembles.

## Phase Goal (derived from ROADMAP)

**As a** logged-in user, **I want to** save my style, format, and constraint preferences once, **so that** every reply the agent gives me follows them without my having to restate them each turn.

> Note: `.planning/ROADMAP.md`'s Phase 3 `**Goal:**` line is stated as an outcome, not in "As a / I want to / so that" form. The story above is a mechanical restatement of that goal line plus Success Criteria 1 and 3 — it adds no scope. Run `/bm:mvp-phase 3` if the canonical user-story form is wanted in ROADMAP.md.

This plan is the end-to-end path proven without a browser: a test does `PUT /api/v1/profile`, then calls `build_system_prompt()` for a chat owned by that user and finds the saved preference text inside the assembled prompt. After this plan, the personalization feature actually works — plan 03-02 only adds the human-facing surface for it.

Locked decisions honored here:
- **D-01** — dedicated `Profile` SQLModel table (NOT reserved keys inside `LongTermMemory`), user-scoped only (no `chat_id`), `user_id` FK to `user.id` with `ondelete="CASCADE"` and `unique=True`.
- **D-02** — write path is REST-only. `agent/tools.py` and `TOOL_REGISTRY` get **zero** changes in this phase. Do not add a `save_profile`/`update_profile` tool.
- **D-03** — `style`, `format`, `constraints` are freeform text, no enums, no mapping layer.

Purpose: PERS-01 (each user has a profile with preferences), PERS-02 (profile attached to every request).
Output: `Profile` table, `agent/profile.py`, `GET`/`PUT /api/v1/profile`, profile injection in `build_system_prompt`, three new test files.
</objective>
