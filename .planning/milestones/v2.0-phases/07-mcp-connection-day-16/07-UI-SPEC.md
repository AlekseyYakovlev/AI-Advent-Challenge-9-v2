# Phase 7 — UI Design Contract

> Visual and interaction contract for the "MCP серверы" section added to the existing Settings modal. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** This phase is a self-contained addition inside `#settings-modal` in `ui/static/index.html` / `ui/static/app.js`. It must visually and behaviorally match the existing app — no new design system, no new component library. All values below are extracted from the current codebase, not invented.

## Spacing Scale

This codebase does not use a strict 8-point token system — it reuses a fixed, repeated set of Tailwind spacing utilities throughout `index.html`. Match these exactly; do not introduce new spacing values.

| Token | Value | Usage (existing precedent) |
|-------|-------|------|
| xs | 4px (`space-y-1`, `gap-1`, `mt-1`) | Icon gaps, tight label-to-input spacing |
| sm | 8px (`p-2`, `space-y-2`, `gap-2`, `mb-2`) | Compact element spacing, list item gaps (matches `invariant-global-list`, `task-list`) |
| compact | 12px (`p-3`, `px-3`, `py-2`) | Card/row padding, input padding (matches `#profile-panel`, textareas, `<select>`) |
| md | 16px (`p-4`, `space-y-4`, `gap-3`→~12px used interchangeably) | Panel padding, form field vertical rhythm (`#settings-form` uses `space-y-4`) |
| lg | 20px (`p-5`, `px-5 py-4`) | Modal body padding, modal header padding (matches `#settings-modal` exactly) |

Exceptions (existing precedent, keep using): `py-1.5` (6px) on `<select>`/small buttons (e.g. `#model-select`, `#invariant-chat-overrides`); `px-2 py-1` on small inline buttons (task action buttons). Apply the same exceptions to MCP row action buttons (Подключить/Изменить/Удалить) and the status badge.

## Component Inventory & Interaction States

Extends the template because this phase adds several stateful, repeated components not covered by the standard template sections — write these states explicitly so planner/executor need zero guessing.

### Server row (`D-02`, `D-03`)

States, top to bottom in the row header:
1. **Collapsed, not connected:** name (`font-semibold text-sm`), status badge (`не подключён`, `text-slate-400`), buttons: `Подключить` (indigo, primary), `Изменить` (`bg-slate-800 hover:bg-slate-700 border border-slate-700`, matches `#btn-settings`), `Удалить` (`text-red-400 hover:text-red-300`, matches invariant delete link style). Disabled server (`enabled=false`): `Подключить` rendered disabled per D-13.
2. **Connecting:** status badge (`подключение…`, `text-sky-400`), all row buttons disabled during the in-flight request (reuse `disabled:opacity-50 disabled:cursor-not-allowed` pattern from `#btn-send`).
3. **Connected:** status badge (`подключено`, `text-emerald-400`) + serverInfo line (`{name} · v{version} · MCP {protocolVersion}`, `text-xs text-slate-500`) + `Инструменты ({n})` collapsible section (default collapsed, `data-fold-toggle` pattern) + button changes to `Отключить` (neutral `bg-slate-800`, not destructive-colored — disconnecting is not data loss).
4. **Error:** status badge (`ошибка`, `text-red-400`) + error message + collapsible stderr block (see above). `Подключить` button remains available to retry.

### Tool list (per connected server, D-03/D-04)

- Header row: `Инструменты ({n})` with a fold toggle (collapsed by default to avoid an overlong modal — matches D-01's "modal may widen and/or scroll to fit").
- Each tool is its own collapsible row (`▸`/`▾`, `data-fold-toggle`):
  - Collapsed: tool name (`text-sm font-semibold`) + one-line description (`text-xs text-slate-400`, truncated with `truncate` if needed).
  - Expanded: parameter list — one row per param: `{name}` (`font-mono text-xs`) + `{type}` (`text-slate-500 text-xs`) + `*` in `text-red-400` if required + description (`text-xs text-slate-400`).
  - `JSON` toggle button (`text-xs text-slate-400 hover:text-white`, right-aligned) reveals raw `inputSchema` pretty-printed in a `<pre>` block, same treatment as the stderr block.

### Add/Edit server form

- Rendered inline (expanding within the MCP section, matching the existing profile/invariant inline-form pattern — not a nested modal) or as a small sub-form appended below the server list — planner's call on exact placement, but it MUST reuse the existing input styling verbatim: `class="w-full rounded-lg bg-slate-800 border border-slate-700 px-3 py-2 text-sm focus:outline-none focus:ring-2 focus:ring-indigo-500"` for text inputs, and the `rows="2"`/`rows="3"` resize-none textarea pattern for `args`/`env`.
- `enabled` toggle: reuse the existing checkbox pattern (`<input type="checkbox" class="rounded">` + inline label), matching `#settings-per-chat`.
- Save button: `Сохранить` (indigo, primary) — but this is a **separate REST call from the modal's own Save button** (per D-01: MCP CRUD is independent of the modal's Save/per-chat checkbox). Cancel button: `Отмена` (`text-slate-400 hover:text-white`), matching `#btn-cancel-settings`.
- No command-path validation on save (D-15) — no inline validation error styling needed for the command field beyond standard empty-required-field handling (reuse the pattern from `#add-user-error`: `<p class="text-xs text-red-400">`).

### Empty state (no servers configured)

Rendered in place of the server list when zero rows exist:
```
Серверы не настроены
Добавьте MCP-сервер, чтобы агент мог подключаться к нему и видеть список инструментов.
```
Styled `text-center text-slate-500 text-sm py-4` (matches the visual weight of other empty states in this app — no existing empty-state precedent to copy exactly, this is a reasonable extrapolation from `text-slate-500`/`text-slate-400` usage throughout).
