## Phase Goal

**As a** user of this agent chat, **I want to** have task state changes strictly validated against an explicit transition graph, **so that** the agent cannot silently skip, reverse, or resurrect lifecycle steps, and every refused attempt leaves a clear, explainable trace instead of a silent no-op or a crash.

<objective>
Close the loop between a domain-layer rejection (Plan 01) and what the user actually sees during a chat turn. Today a failed task tool call is swallowed into `ok=True` tool content that the LLM may or may not mention. After this plan, every task-lifecycle rejection fires the existing WS `{"type": "error", "code": "TOOL_ERROR"}` frame unconditionally, and an illegal *transition* additionally triggers a dedicated justify-or-retract re-prompt.

Purpose: TRANS-02 (clear, explainable rejection in the UI/WS response) and the resume-context half of TRANS-03.
Output: `ok` computed from the handler's own status, `code` discriminators on all three task-lifecycle handlers, the D-08 re-prompt block in the WS turn flow (scoped to `transition_task`), and tests covering the dispatcher, the WS frames, and resume-after-compression.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM tool-call output → `agent/tools.py::dispatch_tool_calls` | Tool names and arguments are model-generated and attacker-influenceable via chat content |
| `agent/ws.py` → browser WebSocket frame | Rejection reasons (server-generated strings) are sent to the client and rendered |
| Rejected tool content → the next LLM prompt | The re-prompt echoes attempted state values back into the model's context |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Information Disclosure | `agent/tools.py` error dicts | mitigate | Ownership is resolved first in `agent/tasks.py` (Plan 01, T-06-01), so a non-owner always reaches the `not_found` branch; the `illegal_transition` branch is unreachable for a task the caller does not own. The `not_found` message text is unchanged from Phase 4 and never reveals whether the id exists elsewhere. Covered by the Plan 01 cross-user test plus a dispatcher test asserting `code == "not_found"` for another chat's task id. |
| T-06-02 | Information Disclosure | WS `TOOL_ERROR` frame `detail` | mitigate | `detail` carries only the server-built rejection reason (task id, state names, legal next states) for a task the authenticated session owns. Do not widen it to include raw exception tracebacks or `result["content"]` for unexpected exception types — this matches CLAUDE.md's "never log/emit full tracebacks" rule. |
| T-06-03 | Denial of Service | D-08 re-prompt round-trip | mitigate | At most one additional `stream_chat` per turn, fired only when at least one result has `name == "transition_task"` AND `code == "illegal_transition"`, and never recursive (the re-prompt's response is streamed as plain text, its tool calls are not dispatched). The `name` filter also keeps repeated pause/resume refusals from multiplying LLM calls. Wrapped in try/except so an LLM timeout degrades to a logged warning instead of a hung turn. |
| T-06-04 | Tampering | `write` field leaking into `memory_writes`/`task_writes` | mitigate | `write` is forced to `None` whenever the handler reports `status == "error"`, so a rejected call cannot inject a phantom write into the `done` frame. Asserted by `done_frame["task_writes"] == []`. |
| T-06-SC | Tampering | pip installs | accept | Zero new packages; `requirements.txt` untouched. If a dependency appears necessary, stop and report rather than installing. |
