<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser confirm (version/title overrides) -> executor | Untrusted values decide what is written |
| agent -> MCP servers | Writes executed in separate processes with the user's git credentials and GitHub token |
| MCP results -> frames | Tool text shown in the browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-18 | Tampering | confirm overrides | mitigate | `validate_version` (format, greater, not taken in local+remote tags) and `sanitize_title` before any write; server re-validates again (27-01) |
| T-27-19 | Tampering | stale plan written after repo changes | mitigate | HEAD re-check against plan.head_sha / commit_sha and strict dirty-tree check (incl. untracked) at confirm time (D-09, D-21) |
| T-27-20 | Tampering | duplicate / parallel confirm | mitigate | `plan.running` guard with try/finally; handler also holds the per-chat lock (27-06) |
| T-27-21 | Information disclosure | arguments/text in logs | mitigate | Logs carry tool names, ok flags, sizes and outcomes only; token never handled by the agent (server env only) |
| T-27-22 | Repudiation | partial release without trace | mitigate | Per-step status frames and result frame with reasons; Release step never reported done unless the tool returned ok with an html_url |
| T-27-23 | Tampering | Release on a commit the tag does not point to | mitigate | Release step only after push DONE, with `commit = plan.commit_sha` (Pitfall 11) |
</threat_model>
