## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP results -> planner | Text from git / GitHub servers parsed in code |
| planner -> chat model | Untrusted commit subjects and PR titles sent to the provider |
| model -> plan | Untrusted text stored in the plan |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-13 | Tampering | build_plan parsing of MCP text | mitigate | Strict JSON parsing via `parse_context` / `parse_commit_page`; ReleaseParseError becomes a notice, never a partial plan |
| T-27-14 | Tampering | model decision | mitigate | Version restricted to code candidates (D-11); title sanitised; changelog limited to three headings (27-02 parsers) |
| T-27-15 | Information disclosure | PR titles / subjects sent to a cloud provider | accept | The chat's own provider is used by design (D-10); same data the user already sends in chats; control runs use LM Studio only (D-16) |
| T-27-16 | Elevation of privilege | planner calling write tools | mitigate | Planner source contains no write tool names (acceptance grep) and tests assert no write call is made |
| T-27-17 | Denial of service | huge ranges | mitigate | 40-page cap (2 000 commits), prompt char budget with shrink, LLM timeout 240 s |
