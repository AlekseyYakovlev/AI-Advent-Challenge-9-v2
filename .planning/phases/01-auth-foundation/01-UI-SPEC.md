# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hard constraint (CLAUDE.md): vanilla JS + Tailwind CDN only, no bundler, no npm packages. `components.json` absent; shadcn gate not applicable (tech stack is not React/Next.js/Vite). |
| Preset | not applicable |
| Component library | none (hand-rolled Tailwind utility classes, matching existing `ui/static/index.html`/`app.js` conventions) |
| Icon library | none — inline SVG (see `overflow-banner` icon in `app.js:450`) or emoji glyphs (⚙️, ⚠️) only, matching existing usage. No icon font/library dependency for Phase 1. |
| Font | System default — Tailwind's default sans-serif stack (`ui-sans-serif, system-ui, ...`). No custom `@font-face`/CDN font is loaded anywhere in the existing codebase; Phase 1 must not introduce one. |

Existing surfaces this phase must extend, not replace: `ui/static/index.html` (chat shell, `#settings-modal`, `#toast-container`), `ui/static/app.js` (`showToast()`, `overflow-banner` pattern). New surfaces: `ui/static/login.html` (per CONTEXT.md D-08), an "Add user" modal inside the authenticated app, and a logout control.

## Spacing Scale

Declared values — this codebase already uses Tailwind's default 4px-increment grid (not a strict 8pt-only scale). Phase 1 must reuse these exact values, not invent new ones:

| Token | Value | Usage (existing precedent) |
|-------|-------|-------|
| 3xs | 4px | `space-y-1` (nav item stacking), icon-text gaps |
| xxs | 6px | `py-1.5` on compact controls (model-select, gear button) |
| xs | 8px | `p-2`, `gap-2` (form field gaps, toast padding-x subset) |
| sm | 12px | `p-3` (stats panel, toast vertical padding) |
| md | 16px | `p-4`, `px-4 py-2` (primary buttons, panels, modal body) — **default spacing unit for Phase 1 forms** |
| lg | 20px | `px-5 py-4` (modal header/body horizontal), `px-5 py-2` (send button) |
| xl | 24px | reserved for section-level breaks if login page needs vertical rhythm beyond the card |

Exceptions: the codebase deliberately mixes 4/6/8/12/16/20 rather than a pure 8pt scale (e.g. `py-1.5` = 6px on compact buttons, `p-3` = 12px on panels). Phase 1 UI (login card, add-user modal, session-expired banner) must match these existing values exactly for visual consistency — do not introduce a stricter 8pt-only grid that would visually diverge from `index.html`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label / helper text | 12px (`text-xs`) | 400 (regular), `text-slate-400`/`text-slate-500` | 1.4 |
| Heading (modal/section title) | 18px (`text-lg`) | 600 (`font-semibold`) | 1.2 |
| Display (login page brand/title) | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 |

Exactly 2 weights are used across the existing app: regular (400, body/labels) and semibold (600, headings/CTA labels via `font-medium`/`font-semibold` — treat both as the single "emphasis" weight tier). Phase 1 must not introduce a third weight (no `font-bold`, no `font-light`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `slate-950` (`bg-slate-950`) | Page/app background (both `index.html` body and new `login.html` body) |
| Secondary (30%) | `slate-900` / `slate-800` (`bg-slate-900`, `bg-slate-900/50`, `bg-slate-800`) | Sidebar, header, modal surfaces, login card, form inputs (`bg-slate-800 border-slate-700`) |
| Accent (10%) | `indigo-600` / `indigo-500` (`bg-indigo-600 hover:bg-indigo-500`) | Reserved for: primary CTA buttons only — "Войти" (login submit), "Создать пользователя" (add-user submit), focus rings (`focus:ring-indigo-500`) on inputs. Never used for body text, borders, or secondary buttons. |
| Destructive | `red-700`/`red-900` (`bg-red-900/50 border-red-700`, toast `bg-red-900/90 border-red-700`) | Login-failure error message/banner only. Not used for logout (logout is non-destructive/reversible — see Copywriting Contract). |
| Warning (secondary semantic) | `yellow-700`/`yellow-900` (`bg-yellow-900/90 border-yellow-700`, `text-yellow-500`) | Session-expired banner on `login.html` (informational, not an error — matches existing `showToast(..., 'warning')` semantics) |

Accent reserved for: the login submit button, the add-user submit button, and focus rings on text inputs — nothing else. Secondary/cancel buttons stay on the slate-800/slate-700 secondary treatment already used by `#btn-cancel-settings` and `#btn-close-settings`.

## Copywriting Contract

All UI copy is in Russian, matching the existing app (`"Новый чат"`, `"Настройки"`, `"Отправить"`, `"Сохранить"`, `"Отмена"`). Phase 1 additions:

| Element | Copy |
|---------|------|
| Primary CTA — login | Button label: **"Войти"** (Log in). Page heading above the form: **"Вход в AI Agent"**. |
| Primary CTA — add user | Button label: **"Создать пользователя"** (Create user). Modal heading: **"Добавить пользователя"**, matching `#settings-modal`'s header pattern (title + × close button). |
| Empty state | Not applicable to Phase 1 — this phase ships only forms (login, add-user), no list/collection view. If a future phase adds a "manage users" list, its empty state must follow this same file's conventions and be specified there. |
| Error state — invalid login | **"Неверное имя пользователя или пароль"** (Invalid username or password), rendered inline below the form fields in `text-red-400` — no modal/toast, stays on `login.html`. |
| Error state — duplicate username (add-user) | **"Пользователь с таким именем уже существует"** (A user with that username already exists), rendered inline under the username field, `text-red-400`, same treatment as the login error. |
| Session-expired banner (D-09) | Heading/body: **"Сессия истекла. Пожалуйста, войдите снова."** (Your session has expired. Please log in again.) — rendered as a `bg-yellow-900/90 border border-yellow-700` banner at the top of `login.html` on 401-triggered redirect, matching the existing `warning` toast palette, not the `error`/red palette (this is expected/benign, not a failure). |
| Destructive confirmation — logout | **No confirmation dialog.** Logout is a single click (button labeled **"Выйти"**) that immediately calls the logout endpoint and redirects to `login.html`. Rationale: logout is low-risk and instantly reversible via re-login (matches CONTEXT.md D-12's "low-stakes, trusted-user coursework" posture) — do not add a confirm-modal here; that would be inconsistent with the rest of the app's friction level (e.g. "New chat" and settings save have no confirmation either). |

## Component Notes for Executor

- **`login.html`**: standalone page (not embedded gate — CONTEXT.md D-08, deliberate deviation, keep it). Structure: `bg-slate-950` full-height body, centered card `bg-slate-900 border border-slate-700 rounded-xl` (same treatment as `#settings-modal`'s inner panel, at `max-w-sm` instead of `max-w-lg`), containing heading, username input, password input (both styled like `#settings-system-prompt`: `bg-slate-800 border border-slate-700 rounded-lg px-3 py-2 text-sm`, `focus:ring-2 focus:ring-indigo-500`), submit button (`bg-indigo-600 hover:bg-indigo-500 rounded-lg px-4 py-2 text-sm font-medium`), and an error-message slot below the form.
- **Session-expired banner**: injected above the form on `login.html`, only when redirected there after a 401 (CONTEXT.md D-09) — not shown on a normal/direct visit to `login.html`.
- **Add-user modal**: reuse `#settings-modal`'s exact DOM/class pattern (`fixed inset-0 z-50 flex items-center justify-center bg-black/60` overlay; `bg-slate-900 border border-slate-700 rounded-xl shadow-xl` panel; header row with title + `×` close button; `p-5 space-y-4` form body; footer with Cancel (`text-slate-400 hover:text-white`) + primary submit (`bg-indigo-600 hover:bg-indigo-500`) buttons, right-aligned). Trigger location left to executor's discretion per CONTEXT.md (modal vs. settings-panel section vs. dedicated page) — modal via a small "Users" control near `#btn-settings` in the header is recommended to minimize new UI surface.
- **Logout control**: place near `#agent-status` in the sidebar footer, styled as a secondary button (`bg-slate-800 hover:bg-slate-700 border border-slate-700 rounded-lg px-3 py-1.5 text-sm`), matching `#btn-settings`'s visual weight — not accent-colored (logout is not the primary action of any screen it appears on).
- **No password-strength UI**: CONTEXT.md D-12 explicitly accepts any non-empty password — do not add a strength meter, complexity hints, or client-side minimum-length validation.
