<objective>
Close the layering loop: the user adds a rule that applies only to this chat, optionally picks the global rule it overrides from a dropdown, and the agent's very next answer is produced under that rule — with both the global and the chat version injected and explicitly labelled so the model can see what was overridden and by what.

Purpose: INV-02 needs a per-chat layer with an explicit precedence rule (D-05's structural `overrides_id` FK, not keyword matching), and INV-03 needs those resolved rules to reach the system prompt on every request. Both must go through one resolver so the prompt and the 05-03 conflict check can never disagree about what is active (05-RESEARCH.md Pitfall 3).
Output: `ChatInvariant` table, per-chat CRUD in `agent/invariants.py`, `resolve_active_invariants`, four `/api/v1/chats/{chat_id}/invariants` routes, the invariants block in `build_system_prompt`, the per-chat UI section with the overrides `<select>`, and three new test modules.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Agent REST | Session-cookie-authenticated; `chat_id`, `invariant_id` and `overrides_id` in path/body are all attacker-controlled |
| Per-chat invariant text → LLM system prompt | User-authored text is injected verbatim into every turn's system prompt — a deliberate instruction channel, bounded by length caps |
| Per-chat invariant text → browser DOM | Re-rendered into the sidebar for the chat owner |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Information Disclosure | `GET/PUT/DELETE /api/v1/chats/{chat_id}/invariants…` | mitigate | Every route calls `await _get_chat_or_404(session, chat_id, current_user.id)` before any query, returning 404 (never 403) so it is not an ownership oracle. Covered by `test_list_chat_invariants_other_users_chat_returns_404`. |
| T-05-07 | Tampering | cross-chat invariant id in the path | mitigate | `_get_chat_invariant_or_404` rejects a row whose `chat_id` does not match the path chat with 404, modelled on the existing `_get_task_or_404`. Covered by `test_update_chat_invariant_from_a_different_chat_returns_404`. |
| T-05-08 | Tampering | `user_id` / `chat_id` supplied in the request body | mitigate | `ChatInvariantCreate` has no `user_id` or `chat_id` field; both come from `current_user.id` and the path. Extra body keys are dropped by Pydantic. |
