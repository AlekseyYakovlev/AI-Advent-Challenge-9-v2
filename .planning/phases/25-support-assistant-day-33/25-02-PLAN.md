- "users": list of objects with string fields: id ("U-1".."U-4"), login, name, email, plan, account_status, app_version, os
- "tickets": list of objects with string fields: id ("T-1001".."T-1006"), client_id (a users[].id), subject, category, status, priority, created_at, updated_at (ISO 8601 UTC), error_text; and messages: list of {"at": ISO string, "author": "client" | "support", "text": string}

Tool output contract (plain text, first line is a one-line summary; plan 05 parses the `Subject:` and `Error:` lines of get_ticket):
get_ticket(id) →
  line 1: "Ticket T-1001: <status>, <priority> priority"
  then lines "Subject: <subject>", "Category: <category>", "Status: <status>", "Priority: <priority>", "Created: <created_at>", "Updated: <updated_at>", "Error: <error_text or none>",
  "Client: <id> @<login>, <name>, <email>",
  "Plan: <plan>; account status: <account_status>; app version: <app_version>; OS: <os>",
  "Messages:" followed by one line per message "- <at> <author>: <text>"
get_user(user) →
  line 1: "User <id> @<login>: <name>, account status <account_status>"
  then "Email: ...", "Plan: ...", "App version: ...", "OS: ...", "Tickets (<N>, <M> open):" and one line per ticket "- <id> [<status>, <priority>] <subject>" (newest updated_at first)
list_user_tickets(user, status=None) → line 1 "<N> tickets for @<login> (<M> open)" (or "... with status <s>") then the same per-ticket lines; zero matches gives "0 tickets for @<login> with status <s>" (never empty)
search_tickets(text, status=None, category=None) → line 1 "Found <M> tickets matching '<text>'" plus "showing <N> of <M>" when cut at 20, then per-ticket lines "- <id> [<status>, <priority>] @<login> <subject>"; zero matches gives "Found 0 tickets matching '<text>'"
Error texts (raised as ToolInputError → MCP isError):
  "ticket '<id>' not found; call search_tickets or list_user_tickets to find a valid id"
  "user '<value>' not found; call search_tickets to find the client's login"
  "invalid ticket id '<value>': use the form T-1001"
  "invalid user '<value>': use a login like ivan or a client id like U-1"
  "unknown status '<value>': use one of <sorted statuses present in the data>"
  "unknown category '<value>': use one of <sorted categories present in the data>"
  "search text must be 1-100 characters"
  "data file is not valid JSON (line <N>): fix the file and retry"
  "data file is invalid: <reason>; fix the file and retry"
  Echoed user input is truncated to 64 characters.
Exposed names in the app (server name `support`): mcp__support__get_ticket, mcp__support__get_user, mcp__support__list_user_tickets, mcp__support__search_tickets.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model / app → MCP tool arguments | ids, logins and search text come from the model or from user-typed identifiers |
| data file → server | the JSON file is edited by the machine owner and may be malformed |
| server output → app prompt | ticket text (client messages) is untrusted data returned to the app |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-05 | Tampering | tool arguments | mitigate | Anchored regexes `_TICKET_ID`, `_CLIENT_ID`, `_LOGIN`; search text 1..100 chars; status/category validated against data; echoed input cut to 64 chars |
| T-25-06 | Information Disclosure | data file path | mitigate | No tool takes a path; the only path is the launch-time `--data`, resolved with `os.path.realpath`, must be a regular file; opened read-only with `open(path, "rb")` |
| T-25-07 | Denial of Service | oversized/malformed JSON | mitigate | 1 MiB cap checked before parse and on read; shape validation; parse errors become tool errors, not crashes |
| T-25-08 | Denial of Service | output flooding | mitigate | `fit_text` cap 18000 < app cap 20000 with marker; search limited to 20 hits |
| T-25-09 | Elevation of Privilege | write capability | mitigate | No write tool exists; test asserts the registered tool set equals the four read tools |
| T-25-10 | Information Disclosure | seed data | mitigate | Fictitious names, `@example.test` emails, no key-shaped strings (grep gate) |
| T-25-SC | Tampering | package installs | accept | No new packages; `mcp==1.30.0` already pinned |
</threat_model>
