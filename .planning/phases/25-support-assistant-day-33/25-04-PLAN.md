## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-typed identifier → tool argument, label, log | the `#T-…` / `@login` token reaches several sinks |
| stored history → prompt | earlier assistant answers are replayed to the model |
| settings row → tool exposure | `mcp_servers_json` decides which servers the model sees |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-14 | Tampering | parse_support identifier | mitigate | Anchored regexes with `(?=\s|$)`, digits 1-6, login charset `[A-Za-z0-9][A-Za-z0-9._-]{0,31}`; failing tokens stay question text; label built from the normalised value only |
| T-25-15 | Tampering | history replay | mitigate | Only pairs whose assistant payload has the `support` key; assistant text capped at 1500 chars and 2000 tokens total; no tool messages replayed; history goes in user/assistant roles, never system |
| T-25-16 | Elevation of Privilege | SupportConfig | mitigate | Primary key is `user_id`; `select_tools` resolves servers through `mcp_config.list_servers(session, user_id)` only |
| T-25-17 | Information Disclosure | logs | mitigate | Log keys carry ids and counts only; acceptance grep forbids `content=`/`question=`/`text=` in log calls |
| T-25-18 | Denial of Service | history walk | mitigate | Walk bounded by `SUPPORT_HISTORY_SCAN_LIMIT = 200` messages |
</threat_model>
