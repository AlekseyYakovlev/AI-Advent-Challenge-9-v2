## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process environment -> repository files | The GitHub token exists only in the environment of the process that runs pytest; nothing in the repository may capture it |
| app -> github-mcp-server.exe -> api.github.com | The token is handed to an external binary and sent to GitHub |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-08 | Information Disclosure | Token leaking into the test file, pytest output, skip reasons or assert messages | mitigate | Token read with `os.environ[TOKEN_ENV]` only; fixed assert messages that never interpolate env or result content; skip reason names the variable only; acceptance check greps the file for token-shaped strings (D-18) |
| T-22-09 | Information Disclosure | Token value returned by the API after saving | mitigate | `test_github_token_value_is_never_returned_by_api` asserts `env_keys` only, on create and on list |
| T-22-10 | Tampering | Write tools exposed although the configuration is meant to be read-only | mitigate | Test asserts none of `WRITE_TOOLS` is in the connected tool set with `--read-only` |
| T-22-11 | Spoofing | Check "passes" with an invalid or expired token | mitigate | A real read call (`list_branches`) must return `ok` |
| T-22-12 | Tampering | Token with write rights (D-17) used by a later configuration without `--read-only` | accept | Accepted by D-17 as a reserve for later Pull Request days; documented in Plan 22-04 that read-only rests on the flag |
| T-22-SC | Tampering | Package installs | accept | No package is installed; the binary is installed by the user from the official release (Plan 22-06) |
