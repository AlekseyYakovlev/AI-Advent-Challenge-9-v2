Five edits to `ui/static/app.js`. Use camelCase for every new identifier (the file is 100% camelCase; the pattern map flags this as a named contract).

1. **State:** add `lastProfile: null,` to the `state` object immediately after `lastMemory: null,` (line 28).

2. **`loadProfile`:** add `async function loadProfile()` directly after `renderMemoryPanel()` ends (around line 304). It calls `const data = await apiFetch('/api/v1/profile');`, assigns `state.lastProfile = data;`, and calls `renderProfilePanel();`. Wrap the body in try/catch and, on failure, `console.error('Failed to load profile:', err);` — same non-fatal treatment `loadChatMemory` gives a failed memory fetch, because a missing profile must never block the chat UI from booting. Note `apiFetch` returns `undefined` after a 401 redirect, so guard with `if (!data) return;` before assigning.

3. **`renderProfilePanel`:** add `function renderProfilePanel()` next to it. Read `const data = state.lastProfile;`, `if (!data) return;`, then set `$('profile-style').value = data.style;`, `$('profile-format').value = data.format;`, `$('profile-constraints').value = data.constraints;`. Use `.value` on the textarea elements and nothing else — never `.innerHTML`, and never `DOMPurify` + `innerHTML`. Profile text is freeform and user-authored; assigning it through `.value` means markup in a preference field can never become live DOM (RESEARCH Pitfall 3).

4. **`saveProfile`:** add `async function saveProfile()` next to them. Build `const body = { style: $('profile-style').value, format: $('profile-format').value, constraints: $('profile-constraints').value };` — always send all three fields, which makes the server's partial-update semantics a no-op distinction for this form. `await apiFetch('/api/v1/profile', { method: 'PUT', body: JSON.stringify(body) })`, assign the response to `state.lastProfile`, and `showToast('Профиль сохранён', 'success');`. Wrap in try/catch and on failure call `showToast('Не удалось сохранить профиль. Проверьте соединение и попробуйте снова.', 'error');`. Both strings are verbatim from UI-SPEC's Copywriting Contract — do not paraphrase them. Do not re-render the panel after a successful save (the user's typed text is already on screen; re-rendering would fight an in-flight edit).

5. **Wiring:** in `bindEvents()`, register `$('btn-save-profile').addEventListener('click', () => { saveProfile().catch((err) => showToast(err.message, 'error')); });` alongside the other button bindings. In `init()`, call `await loadProfile();` once, after `await loadModels();` and before the `try { await loadChats(); ... }` block. Call it exactly once at startup — **not** from `selectChat()` and **not** from the `case 'done':` branch of `handleWsMessage` — because the profile is user-scoped, not chat-scoped (D-01), unlike `loadChatMemory` which correctly reloads per chat.

Do not touch `loadChatMemory`, `renderMemoryPanel`, `saveSettings`, or any WebSocket code.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server response → DOM | Profile text originating from the user is written back into the page |
| browser → `PUT /api/v1/profile` | Request crosses the session-cookie boundary; `apiFetch` supplies `credentials: 'include'` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | Tampering (stored XSS) | `renderProfilePanel` | mitigate | Profile values are assigned only via `HTMLTextAreaElement.value`; `innerHTML` count in `app.js` is gated to stay at 11. Markup in a preference field can never execute. |
| T-03-08 | Information disclosure | expired session on the profile panel | mitigate | Both calls go through `apiFetch`, which redirects to `login.html?expired=1` on 401 instead of rendering stale or empty data as if authenticated. Gated by the raw-`fetch` count assertion. |
| T-03-09 | Denial of service | oversized paste into a textarea | transfer | Length is enforced server-side (`PROFILE_FIELD_MAX_LENGTH`, 422); the client surfaces the failure as the UI-SPEC error toast rather than duplicating validation logic that could drift from the server's. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No packages installed; the frontend remains vanilla JS + existing CDN scripts (`CLAUDE.md` hard constraint). Nothing to audit. |
</threat_model>
