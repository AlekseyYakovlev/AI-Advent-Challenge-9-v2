Routes (agent/main.py):
- `GET /api/v1/chats/{chat_id}/memory` -> `{ chat_id, short_term_message_count, working: [entry], long_term: [entry] }`, entry = `{ id, key, value, updated_at }`; 404 for a foreign chat; long-term is user-scoped (same list from every chat)
- `PUT /api/v1/memory/long-term/{entry_id}` body `{ "key"?: string, "value"?: string }` -> 200 entry | 401 | 403 (foreign Origin) | 404 `Запись памяти не найдена` (unknown or foreign id) | 409 `Запись с таким ключом уже существует` | 415 (not JSON) | 422 (blank key, whitespace-only value, key > 200, value > 50 000, no field)
- `DELETE /api/v1/memory/long-term/{entry_id}` -> 204 | 401 | 403 | 404

CRUD layer (agent/memory.py): `get_long_term_memory`, `update_long_term_memory`, `delete_long_term_memory`, `MemoryKeyConflictError`; `save_long_term_memory` (LLM tool upsert by key) unchanged.

Frontend (ui/static/app.js, memory region between `loadChatMemory` and `loadChatTasks`): `state.editingMemory`, `saveLongTermMemory`, `deleteLongTermMemory`, `buildMemoryEntryRow`, `buildMemoryEditForm`, `renderMemoryEntries(container, entries, { editable })`.
UI strings: buttons `Редактировать`, `Удалить`, `Сохранить`, `Отмена`; toasts `Запись памяти обновлена`, `Запись памяти удалена`, `Заполните ключ и значение`; confirm text starts with `Удалить запись «<key>»`.
</interfaces>
