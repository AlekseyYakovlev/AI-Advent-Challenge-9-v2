<objective>
Verify the memory edit/delete feature in a real browser on an isolated copy of the app (UI :18000 / Agent :18001), with a machine-checkable result.

Purpose: the buttons, the inline form, the `confirm()` dialog, the draft that survives a re-render and the plain-text rendering are frontend behaviour that pytest cannot observe. This plan was split out of 11-03 (plan-checker revision) so that the harness, the eleven browser scenarios and the fix-and-rerun loop have their own context budget, and so that a failed or skipped browser run is detected by automated verify and not only by SUMMARY prose.
Output: a recorded result for scenarios S1-S11 (or an explicit "Browser UAT NOT RUN: <reason>"), no file created in the repository by the UAT itself.
</objective>

- `reason`: non-empty string when `status` is `NOT_RUN`, otherwise an empty string

- `scenarios`: object with exactly the keys `S1` ... `S11`, each `"PASS"` or `"FAIL"` (empty object when `NOT_RUN`)

- `dialogs`: list of every recorded dialog message; `page_errors`: list of every `pageerror` text
