<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chat question -> retrieval pipeline | untrusted text drives embedding, FTS and LLM stage calls |
| LLM stage output -> chunk selection | model replies influence which chunks reach the answer prompt |
| pipeline trace -> stored message / browser | trace is persisted and rendered later |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-16 | Information disclosure | hybrid stage | mitigate | pipeline passes only kb.id of the KB object it was given (ownership-checked by rag_turn._load_kb); fts_search and load_chunks_by_ids filter by kb_id; candidates without a row in that KB are dropped |
| T-15-17 | Tampering | rewrite stage | mitigate | rewritten text is used only as an embedding/FTS input (FTS string rebuilt through build_fts_query); the original query is always searched too (D-12), so a hostile rewrite cannot remove candidates; the raw-cosine threshold still gates what it adds |
| T-15-18 | Tampering | LLM rerank stage | mitigate | scores only reorder already-surviving chunks within the top 10; they cannot add chunks or bypass the threshold (D-07) |
| T-15-19 | Information disclosure | trace | mitigate | metadata only (ids, file, section, page, scores, statuses); test asserts no `text` key; log line carries counts and codes only |
