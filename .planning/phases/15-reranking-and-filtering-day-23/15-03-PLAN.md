<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user question -> SQLite FTS5 MATCH | free text reaches a query language |
| FTS row ids -> chunk content | ids from a shared virtual table are turned into chunk text |
| user question / chunk text -> LLM provider | data sent to the chat's provider (local LM Studio or cloud) |
| LLM reply -> application | model output is parsed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-10 | Tampering | fts_search | mitigate | MATCH string from build_fts_query (quoted tokens only), passed as a bound parameter; OperationalError caught and converted to FtsQueryError; grep gate forbids string-built SQL |
| T-15-11 | Information disclosure | fts_search / load_chunks_by_ids | mitigate | `kb_id = :kb` on the FTS query and `KbChunk.kb_id == kb_id` on the row load; cross-KB isolation test; the caller (15-04) passes only a KB already ownership-checked by rag_turn._load_kb |
| T-15-12 | Tampering | rewrite_query / llm_rerank | mitigate | prompts built by rag_rank with data tags; replies go through validate_rewrite / parse_rerank_scores; output is never executed |
| T-15-13 | Denial of service | LLM stage calls | mitigate | asyncio.wait_for with settings.RAG_LLM_STAGE_TIMEOUT; max_tokens 96 / 200; rerank batch capped at 10 chunks of 600 chars |
| T-15-14 | Information disclosure | stage logging | mitigate | logs carry stage, model, error type and token counts only; never question text, prompt, chunk text or keys |
| T-15-15 | Information disclosure | chunk text sent to provider | accept | same data already goes to the same provider in the answer prompt (Phase 14); no new recipient (D-11: chat's own provider) |
| T-15-SC | Tampering | package installs | accept | no packages are installed in this phase |
</threat_model>
