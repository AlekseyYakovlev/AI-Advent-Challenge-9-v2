<objective>
Extend the storage and the per-chat settings API for two-stage retrieval: new `ChatRagConfig` columns with an idempotent migration, a trigger-synced SQLite FTS5 table over `kbchunk` with backfill, the per-model calibrated-threshold lookup, and partial-update semantics on `PUT /api/v1/chats/{id}/rag`.

Purpose: RANK-01 (candidate-K, final-K and threshold configurable per chat), the storage half of RANK-04 (FTS5) and the lookup half of RANK-07 (per-model threshold constants). This plan has no dependency on the Phase 14 UI/eval plans 14-06..14-08 (which are executed by now).
Output: schema + migration, FTS table/triggers/backfill, threshold lookup, extended REST contract, tests.

Note on CALIBRATED_THRESHOLDS: per D-15 the numeric values may only come from the frozen calibration set, which is measured in plan 15-08 and written into the constant in plan 15-09. In this plan the dict is created empty, which by D-10 means every model resolves to 0 (no cut) until calibration has been run. Do not invent numbers here (0.62 in CONTEXT.md mockups is not a measured value).
</objective>
