# Phase 8 — UI Design Contract

> Visual and interaction contract for the Scheduler UI (Day 18). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 08-CONTEXT.md (D-15, D-16, D-17 locked), existing `ui/static/index.html` + `ui/static/app.js` patterns, CLAUDE.md (vanilla JS + Tailwind CDN + Marked + DOMPurify only).

**Scope of this contract:** one new foldable sidebar panel `#scheduler-panel`, one create-job modal, one run-result modal, live-update behavior over `/ws/events`, and toasts. No changes to the chat area, header, or existing panels beyond inserting the new panel.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not applicable: no React/Vite/npm; project constraint is vanilla JS + CDN) |
| Preset | not applicable |
| Component library | none — hand-written Tailwind utility markup built with `document.createElement` / `textContent` (same as `renderTaskPanel`, `renderMcpServerRow`) |
| Icon library | none — Unicode glyphs only, matching existing usage (`▸`/`▾` fold caret, `⏸`, `&times;` close). No icon fonts or SVG packages. |
| Font | Tailwind default `font-sans` system stack (inherited from `<body class="antialiased">`); `font-mono` only for cron expressions and tool-trace `<pre>` |

Existing theme to match (do not re-specify, reuse): dark slate theme, `bg-slate-950` page, `bg-slate-900` sidebar/modals, `bg-slate-800` cards/inputs, `border-slate-700/800`, indigo-600 primary buttons, `focus:ring-2 focus:ring-indigo-500` inputs, `hidden` class toggling for panels/modals, `showToast(message, type)` for feedback, native `confirm()` for destructive confirmation, `renderMarkdown()` (`marked.parse` + `DOMPurify.sanitize`) for Markdown.

## Spacing Scale

Declared values (all multiples of 4; expressed as the Tailwind classes already used in the sidebar panels):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `py-1`, `mt-1`) | Gaps between chips/buttons in a card, run-row vertical padding |
| sm | 8px (`px-2`, `gap-2`, `mb-2`, `space-y-2`) | Card inner padding, spacing between job cards, button padding |
| md | 16px (`p-4`, `space-y-4`) | Modal body vertical rhythm between form fields |
| lg | 24px | Not used inside the panel; modal header/footer use 20px (`px-5 py-4`/`p-5`) to match `#settings-modal` (see exception) |
| xl | 32px | Not used |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions:
- Panel outer padding is 12px (`p-3`) to match `#memory-panel`, `#task-panel`, `#invariants-panel` exactly (12 is a multiple of 4).
- Modal padding is 20px (`p-5`, `px-5 py-4`) to match the existing `settings-modal` / `add-user-modal` shells (20 is a multiple of 4).
- Do NOT use half-step classes (`py-1.5`, `px-1.5`, `gap-1.5`) in new markup — they produce 6px values outside the scale. (The existing header select uses `py-1.5`; do not copy it.)
- Touch targets: this is a desktop, single-user local app; small action buttons stay `px-2 py-1 text-xs` (existing convention). No 44px minimum applies.

Panel dimensions: sidebar is fixed `w-64` (256px); the panel inherits `max-h-72 overflow-y-auto` like its siblings. Long titles/prompts truncate (`truncate` + `title` attribute) — never wrap the sidebar wider.

## Typography

Tailwind default sizes/line-heights are used (they are what every existing panel renders). Exactly 3 sizes and 2 weights are used by this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (inputs, job title, modal body text, result text) | 14px (`text-sm`) | 400 regular (job title: 600) | 1.43 (Tailwind `text-sm` = 20px) |
| Label (panel text, chips, timestamps, helper text, buttons in panel, form hints) | 12px (`text-xs`) | 400 regular (panel heading + counts: 600) | 1.33 (Tailwind `text-xs` = 16px) |
| Heading (modal `<h2>` only) | 18px (`text-lg`) | 600 semibold | 1.56 (Tailwind `text-lg` = 28px) |
| Display | not used in this phase | — | — |

Weights: **regular (400)** and **semibold (600)** only. Do not use `font-medium` (500) in new markup — primary buttons in this phase use `font-semibold` instead of the `font-medium` seen in older buttons. The panel heading `<h3>` is `text-xs font-semibold text-slate-300` exactly as the sibling panels.

Rendered Markdown inside the run-result modal uses the existing `.message-content` class (already styles `pre`, `code`, `p`, `ul/ol`), so no new CSS is required; `<pre>` blocks keep `overflow-x-auto`.

## Color

Existing palette is reused; no new hues are introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | slate-950 `#020617` | Page background; modal backdrop is `bg-black/60` |
| Secondary (30%) | slate-900 `#0f172a` (sidebar, modal shell) and slate-800 `#1e293b` (job cards, run rows, inputs, neutral buttons) | Panel surface, cards, inputs; borders `slate-700` `#334155` / `slate-800` |
| Accent (10%) | indigo-600 `#4f46e5` (hover indigo-500 `#6366f1`) | Reserved list below |
| Destructive | red-700 `#b91c1c` (hover red-600) for filled destructive button; red-400 `#f87171` for destructive text/links and error text | Cancel/Delete job only; `failed` status text; error messages |

Accent reserved for (only these):
1. The "Создать задание" / "Сохранить" submit button in the create modal
2. The "+ Новое задание" button in the panel body
3. "Продолжить" (resume) button on a paused job (mirrors existing task-panel resume button)
4. Input focus ring (`focus:ring-indigo-500`) in the create form
5. Not used for status text, badges, links, or the run-result modal.

Status colors (text-only chips, same technique as `TASK_STATE_BADGE_CLASSES` / `MCP_STATUS_BADGE_CLASSES`; chips are `rounded px-1 text-xs`, no filled backgrounds):

| Status | Tailwind text class | Label (RU) |
|--------|--------------------|-----------|
| job `active` | `text-sky-400` | активно |
| job `paused` | `text-amber-400` | на паузе |
| job `completed` | `text-emerald-400` | завершено |
| job `cancelled` | `text-slate-500` | отменено |
| run `running` | `text-sky-400` + leading pulsing dot (`animate-pulse motion-reduce:animate-none`) | выполняется |
| run `success` | `text-emerald-400` | успешно |
| run `failed` | `text-red-400` | ошибка |
| run `skipped` | `text-slate-400` | пропущено |
| run late/missed marker | `text-amber-400` chip after status | с опозданием |

Color is never the sole signal: every status has a text label (and `running` additionally has the dot).

## Layout & Component Contract

### 1. `#scheduler-panel` (sidebar, inserted after `#invariants-panel`, before `#agent-status`)

Container classes identical to siblings: `border-t border-slate-800 p-3 text-xs text-slate-400 overflow-y-auto max-h-72`.

Heading row (`h3.text-slate-300.font-semibold.mb-2.flex.items-center.justify-between`):
- Left: `Расписание` + count `<span id="scheduler-count" class="text-white font-semibold">0</span>` (count of active + paused jobs) + a running indicator `<span id="scheduler-running-badge" class="text-sky-400 font-semibold hidden">` showing `N выполняется`-style count of currently running runs (hidden when 0).
- Right: fold toggle `<button data-fold-toggle="scheduler-panel-body" aria-expanded="false" title="Свернуть/развернуть">▸</button>` — handled by the existing `setupFoldablePanels()` with no changes. Default state: collapsed (`hidden` body), same as siblings.

Body `#scheduler-panel-body.hidden`:
- `+ Новое задание` full-width button (`w-full rounded-lg bg-indigo-600 hover:bg-indigo-500 px-4 py-2 text-sm font-semibold transition`) opens the create modal.
- `#scheduler-list.space-y-2.mt-2` — job cards.
- Empty state (when zero jobs — includes cancelled/completed only if the list endpoint returns them; list shows ALL non-deleted jobs, newest `next_run_at` first, active/paused before completed/cancelled).

### 2. Job card (`rounded-lg bg-slate-800 px-2 py-1`, same as task card)

Row 1 (clickable header, `button type="button"` w/ `aria-expanded`, toggles run history): `▸/▾` caret, job title (`text-sm font-semibold text-slate-300 truncate`, `title` = full title), job status chip (right).
Row 2: schedule summary (`text-slate-400`): 
- once → `Однократно · 26.09 14:05`
- interval → `Каждые 5 мин` (largest whole unit: сек / мин / ч)
- cron → `Cron: */5 * * * *` (`font-mono`)
- if `max_runs`: append ` · запусков: 2/5`; otherwise ` · запусков: 2`
Row 3: `Следующий: 26.09 14:05` (`text-slate-500`; `—` when none, e.g. paused/completed/cancelled) and last run chip: `Последний: <run status chip>`; omit when no runs.
Row 4 (actions, `mt-1 flex flex-wrap gap-1`), by job status:
- `active`: `Запустить сейчас` (neutral), `Пауза` (neutral), `Отменить` (destructive filled), 
- `paused`: `Запустить сейчас` (neutral), `Продолжить` (accent), `Отменить` (destructive filled)
- `completed` / `cancelled`: only `Удалить` (red-400 text link style, as MCP `Удалить`)
- `Удалить` is also available for active/paused as a text-link (`text-red-400 hover:text-red-300`) placed last.
Button classes: neutral = `rounded-lg bg-slate-800 hover:bg-slate-700 border border-slate-700 px-2 py-1 text-xs font-semibold transition disabled:opacity-50 disabled:cursor-not-allowed`; accent = `rounded-lg bg-indigo-600 hover:bg-indigo-500 px-2 py-1 text-xs font-semibold transition`; destructive = `rounded-lg bg-red-700 hover:bg-red-600 px-2 py-1 text-xs font-semibold transition`.
While a job has a run in `running` state, `Запустить сейчас` is disabled and shows `title="Задание уже выполняется"`.
Origin: if `origin_chat_id` is set, no extra UI (provenance is API-only this phase).

### 3. Run history (expands under the card header; `mt-1 space-y-1`, max 20 most-recent runs shown, newest first)

Each run row is a `button type="button"` (`w-full text-left rounded bg-slate-900 hover:bg-slate-700 px-2 py-1 flex items-center justify-between gap-2`): 
- left: start time `26.09 14:05:12` (`text-slate-500`)
- middle: status chip (+ `с опозданием` chip if flagged)
- right: duration `12 с` / `1 мин 5 с` (`text-slate-500`; omit for `running`/`skipped`).
Click opens the run-result modal. `skipped` rows open the modal too (body shows the skip reason). Empty: `Запусков пока не было`.

### 4. Create-job modal `#scheduler-create-modal`

Rationale: 256px sidebar is too narrow for a 7-field form; a modal reuses the existing shell (`hidden fixed inset-0 z-50 flex items-center justify-center bg-black/60` + `bg-slate-900 border border-slate-700 rounded-xl shadow-xl w-full max-w-lg mx-4 max-h-[90vh] overflow-y-auto`), header `Новое задание` (h2 `text-lg font-semibold`) + `&times;` close (`aria-label="Закрыть"`), form `p-5 space-y-4`. Fields (label `block text-sm text-slate-400 mb-1`, inputs `w-full rounded-lg bg-slate-800 border border-slate-700 px-3 py-2 text-sm focus:outline-none focus:ring-2 focus:ring-indigo-500`), all with `<label for>`:

| Field | Control | Notes |
|-------|---------|-------|
| Название | text, `maxlength=200`, required | placeholder `Например: Сводка по репозиторию` |
| Что сделать агенту (промпт) | textarea rows=4, `maxlength=4000`, required | helper `Агент выполнит этот текст как запрос и сохранит ответ в истории запусков` |
| Тип расписания | select: `Однократно` / `Интервал` / `Cron` | default `Однократно`; switching shows only the matching field group |
| Однократно | radio pair `Через N секунд` (number, min 1) / `В указанное время` (`datetime-local`) | maps to `delay_seconds` or `run_at`; `datetime-local` value is machine-local time (D-07); helper `Локальное время` |
| Интервал | number `Каждые` (min 1) + unit select `секунд / минут / часов` | converted to `interval_seconds`; minimum effective interval 10 s (client hint: `Минимальный интервал — 10 секунд`; server is source of truth) |
| Cron | text (`font-mono`) | placeholder `*/5 * * * *`; helper `5 полей: минута час день месяц день_недели. Время — локальное время машины агента.` |
| Модель | select populated from `state.models`, preselected `state.selectedModel`; falls back to disabled option `Нет моделей` | helper `Если модель будет недоступна, запуск завершится ошибкой` |
| Максимум запусков | number, min 1, optional, hidden/disabled for `Однократно` | placeholder `Без ограничения`; label `Максимум запусков (необязательно)` |

Inline error line `<p id="scheduler-create-error" class="text-xs text-red-400">` above the buttons (same as `#mcp-form-error`). Footer: `Отмена` (text-only `text-slate-400 hover:text-white`) + primary submit `Создать задание` (accent). Submit disabled while request in flight; on success: close modal, refresh list, `showToast('Задание создано', 'success')`.

### 5. Run-result modal `#scheduler-run-modal`

Same shell as `settings-modal`, `max-w-2xl`. Header: job title (h2 `text-lg font-semibold truncate`) + `&times;` close (`aria-label="Закрыть"`). Sub-header (`text-xs text-slate-500`): status chip, `начало 26.09 14:05:12`, duration, `с опозданием` chip if flagged. Body (`p-5 space-y-4`):
1. **Результат** — final answer rendered via `renderMarkdown(text)` (Marked + `DOMPurify.sanitize`) into a `div.message-content.text-sm`, assigned with `innerHTML`; never assign raw text via `innerHTML` without `renderMarkdown`. 
2. **Ошибка** (only for `failed`) — `bg-red-900/30 border border-red-700 rounded-lg p-3 text-sm text-red-400` with `textContent` of the error message.
3. **Ход выполнения (инструменты)** — collapsed by default toggle (`▸ Показать ход выполнения`, same pattern as MCP stderr toggle); when open, list of tool calls, each `name` (`font-mono text-xs text-slate-300`) + args/result in `<pre class="text-xs text-slate-400 bg-black/30 rounded-md p-2 overflow-x-auto whitespace-pre-wrap">` set via `textContent`. Hidden entirely when the run had no tool calls.
4. `skipped` runs: body is a single line `Запуск пропущен: предыдущий запуск ещё выполнялся`.
5. `running` runs: body shows `Задание выполняется…` with the pulsing dot; when the `run_finished` event arrives for this run the modal content refreshes in place.

Modal behavior (both modals): opened by removing `hidden`; closed by `×`, backdrop click (target === modal root), and `Escape`; on open focus moves to the first field (create) or the close button (result); on close focus returns to the element that opened it. Add `role="dialog" aria-modal="true" aria-labelledby=<h2 id>`. Only one scheduler modal open at a time.

### 6. Live updates (D-17) — UI behavior

- Open `/ws/events` once after login/page load (`new WebSocket(`${WS_BASE}/ws/events`)`); reuse the reconnect approach of the chat socket (`STOP_RECONNECT_CODES`, exponential backoff capped at `MAX_RECONNECT_DELAY`). On every (re)connect and on first opening of the panel body, call `GET /api/v1/scheduler/tasks` to re-sync (`state.lastSchedulerTasks`).
- Events applied to `state.lastSchedulerTasks` then `renderSchedulerPanel()` (full `replaceChildren()` re-render, same as `renderTaskPanel`), preserving expanded-card ids in `state.schedulerExpanded` (Set) so expansion is not lost on re-render:
  - `run_started` → job shows `running` chip and pulsing dot; run row appears at the top of history.
  - `run_finished` → run row updates status/duration; job "Последний" chip and "Следующий" time update; if the result modal is open for that run, refresh it.
  - job status change (paused/resumed/cancelled/completed/deleted) → card updates or is removed.
- Toasts on `run_finished` only: `success` → `showToast('Задание «{title}» выполнено', 'success')`; `failed` → `showToast('Задание «{title}» завершилось с ошибкой', 'error')`; `skipped` → no toast.
- Connection loss: no blocking UI; the panel keeps working via manual actions (each action re-fetches the list). While the events socket is disconnected, poll `GET /api/v1/scheduler/tasks` every 10 s only when the panel body is expanded (stop on reconnect). No visible "offline" banner for this socket (Agent health is already shown by `#agent-status`).
- All timestamps from the server are UTC ISO strings; render in the browser's local time with `toLocaleString('ru-RU', { day: '2-digit', month: '2-digit', hour: '2-digit', minute: '2-digit' })` (add `second: '2-digit'` for run rows). Reuse `formatTaskTimestamp` if its output already matches; otherwise add one shared helper.

### 7. Interaction & state rules

- Every action button disables itself while its request is in flight and re-enables in `finally`.
- After any mutating action (pause/resume/run now/cancel/delete/create) re-fetch the list (do not trust the WS echo alone) and show the toast below.
- `Запустить сейчас` shows toast `Запуск начат` (info) immediately; progress arrives via WS.
- Keyboard: card header and run rows are real `<button>`s (Tab/Enter/Space work); visible focus ring `focus:outline-none focus:ring-2 focus:ring-indigo-500`; `Escape` closes modals; `Enter` in single-line inputs submits the create form; `Enter` in the prompt textarea inserts a newline.
- All dynamic text (titles, prompts, results, errors, tool traces, cron strings) is inserted via `textContent`, or `renderMarkdown()` for the result body only. No template-string `innerHTML` with server data.

All UI text in Russian (matches the rest of the app).

| Element | Copy |
|---------|------|
| Panel title | `Расписание` |
| Primary CTA (panel) | `+ Новое задание` |
| Primary CTA (modal submit) | `Создать задание` |

| Empty run history | `Запусков пока не было` |
| Error state (load list) | `Не удалось загрузить расписание. Проверьте соединение и попробуйте снова.` |
| Error state (action) | `Не удалось выполнить действие. Проверьте соединение и попробуйте снова.` (or the server `detail` string when the server returns a validation message) |
| Error state (create validation) | `Заполните название и промпт`; `Укажите корректное расписание`; cron invalid → `Некорректное cron-выражение. Нужно 5 полей: минута час день месяц день_недели.`; past `run_at` → `Время запуска уже прошло` |
| Run failed (modal) | prefix `Ошибка выполнения:` + server error text; model unavailable example rendered as received (`Модель недоступна: LM Studio не запущен`) |
| Run timeout (modal) | server text; UI adds nothing (server writes `Превышено время выполнения (120 с)`) |
| Toasts (success) | `Задание создано` / `Задание поставлено на паузу` / `Задание возобновлено` / `Задание отменено` / `Задание удалено` / `Запуск начат` (info) / `Задание «{title}» выполнено` |
| Toasts (error) | `Задание «{title}» завершилось с ошибкой`; failed actions use the action error copy above |
| Destructive: Отменить | `confirm('Отменить задание «{title}»? Будущие запуски не состоятся, история запусков сохранится.')` |
| Destructive: Удалить | `confirm('Удалить задание «{title}» и всю историю его запусков? Это действие нельзя отменить.')` |

Button labels: `Пауза`, `Продолжить`, `Запустить сейчас`, `Отменить`, `Удалить`, `Отмена` (close form), `×` (aria-label `Закрыть`).

Destructive actions in this phase: Отменить (soft cancel, confirm via native `confirm()`), Удалить (hard delete of job + runs, confirm via native `confirm()`). Pause/Resume/Run now are non-destructive and need no confirmation. (Native `confirm()` is the established project pattern for `cancelTask`, `deleteGlobalInvariant`, `deleteMcpServer`; do not introduce a custom confirm dialog.)

Status/schedule label maps live as JS constants next to the panel code (`SCHEDULER_JOB_STATUS_LABELS`, `SCHEDULER_RUN_STATUS_LABELS`, `*_BADGE_CLASSES`), following `TASK_STATE_LABELS` / `MCP_STATUS_LABELS` naming.
