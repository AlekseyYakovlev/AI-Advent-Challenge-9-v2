<objective>
Wire the shared message limit and the generation queue into both chat channels: the WebSocket
receive loop and the HTTP chat endpoint use one rate check, and every chat turn runs inside a
generation slot through one wrapper that announces the queue and reports the wait.

Purpose: LIM-01, LIM-02, LIM-05; the limit and queue tests of VER-06.
Output: changes in `agent/ws.py` and `agent/http_chat.py`, two new test files, and the two
existing tests that the new behaviour breaks (`test_ws_rate_limiting`,
`test_success_body_has_exact_keys_and_stats`) updated in this plan.

Not in this plan: the login lockout, `/debug/routes`, the supervisor (plan 20-03), any
frontend change (plan 20-04), docs (plan 20-07). Deferred ideas that must not appear: a bounded
queue or a 503 "server overloaded" answer, a wait timeout, a route or UI exposing the limits.
</objective>
