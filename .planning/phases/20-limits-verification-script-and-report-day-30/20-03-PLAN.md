<objective>
Protect the login route with a temporary lockout, put `/debug/routes` behind authentication,
and give the supervisor a readiness signal that still works once that route is guarded.

Purpose: LIM-03 and LIM-04, plus their tests for VER-06.
Output: changes in `agent/main.py`, `shared/origins.py`, `ui/supervisor.py`; one new test
file; four existing test files updated because this plan changes what they assert.

The auth change on `/debug/routes` and the supervisor probe change are in the same task on
purpose. Research found a hidden failure: with auth added and the probe unchanged, the probe
never gets 200, `_wait_for_agent_ready` runs three cycles of 20 attempts (about 30 seconds plus
forced restarts) on every start without raising, and `tests/test_supervisor.py` stays green.
Tasks 2 and 3 add tests that fail in exactly that situation.

Not in this plan: the login page message (plan 20-04), the chat channels (plan 20-02), docs
(plan 20-07). Deferred ideas that must not appear: persisting lockouts in SQLite, a route or UI
element exposing the limits.
</objective>
