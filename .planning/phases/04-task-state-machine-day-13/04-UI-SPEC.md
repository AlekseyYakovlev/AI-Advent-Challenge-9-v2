# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase adds a single new sidebar tab ("Задачи" / Tasks) to the existing single-page app. There is no new visual system to design — the contract below is extracted directly from the codebase's existing, already-shipped Memory (`#memory-panel`) and Profile (`#profile-panel`) sidebar tabs (Phases 2–3) per `04-CONTEXT.md` D-10/D-11. All values are descriptive of what already exists in `ui/static/index.html` / `ui/static/app.js`, not new inventions, except where explicitly marked "new for this phase."

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — vanilla JS + Tailwind CDN, no bundler/npm (hard constraint, `CLAUDE.md` §Hard constraints) |
| Preset | not applicable — no `components.json`, no shadcn; confirmed absent in repo root |
| Component library | none — hand-rolled Tailwind utility markup, mirrored from `#memory-panel`/`#profile-panel` |
| Icon library | none — plain emoji glyphs used sparingly for icon-like affordances (e.g. 👥, ⚙️ in header buttons); no SVG/icon-font library. Task tab should avoid introducing new icon glyphs beyond a single pause glyph (⏸) already implied by the "paused" state, to stay consistent with the app's minimal-icon convention |
| Font | Tailwind default sans stack (`ui-sans-serif, system-ui, ...`) — no custom `@font-face`/webfont declared anywhere in `index.html` |

shadcn gate: not applicable. This project is FastAPI + vanilla JS (no React/Next.js/Vite), so the shadcn initialization gate from the researcher playbook does not apply. Registry Safety section below is marked "not applicable" for the same reason.

## Spacing Scale

Declared values (must be multiples of 4) — taken from actual utility classes already in use across `#memory-panel`/`#profile-panel`/modals:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | `gap-1`/`space-y-1` — inline gaps between a task's state badge and pause tag |
| sm | 8px | `gap-2`/`space-y-2`/`mb-2` — compact stacking between task cards, between a task's meta rows |
| md | 12px | `p-3` — panel container padding (matches `#memory-panel`/`#profile-panel` exactly) |
| lg | 16px | `p-4` — used only if the task tab ever needs a larger container (modals use this); default panel padding stays at 12px (md) to match precedent |
| xl | 24px | not used in sidebar panels this phase |
| 2xl | 32-48px | not used in sidebar panels this phase |

Exceptions: 12px (`p-3`) and 20px (`p-5`, used only in modal headers/forms, not in this phase's sidebar panel) are already established in the codebase as valid steps on top of the named scale — both are still multiples of 4, so no deviation from the "multiples of 4" rule, just a denser step than the template's default `md=16`. The new Task tab uses `p-3` (12px) as its outer container padding to exactly match `#memory-panel`/`#profile-panel`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular, no weight class) | 1.5 (Tailwind default for `text-sm`) |
| Label | 12px (`text-xs`) | 400 (regular) | 1.4 (Tailwind default for `text-xs`) — used for task meta: timestamps, state-transition notes, secondary counts |
| Heading | 12-14px (`text-xs`/`text-sm`) | 600 (`font-semibold`) | 1.3 — panel title "Задачи" mirrors `#memory-panel h3` (`text-slate-300 font-semibold`, inherits parent `text-xs`); per-task title uses `text-sm font-semibold` for legibility since task titles are the primary scan target in the list |
| Display | 12px (`text-xs`) | 600 (`font-semibold`), color `text-white` | 1.4 — task-count badge in the tab header, mirrors `memory-working-count`/`memory-long-term-count` exactly (size stays small; emphasis comes from color+weight, not size, per existing convention) |

Weights: exactly 2 primary weights — 400 regular (body/labels) and 600 semibold (headings/counts/emphasis). Pre-existing exception carried unchanged from the app's global chrome: all buttons (including this phase's new Pause/Resume/Cancel buttons) use `font-medium` (500), matching every existing button in `index.html` (`btn-new-chat`, `btn-save-profile`, `btn-send`, etc.) — this is not a new weight introduced by this phase, just inherited button styling.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-slate-950` | App background (`<body>`) — unchanged, this phase adds no new page-level surface |
| Secondary (30%) | `bg-slate-900` / `bg-slate-800`, borders `border-slate-800`/`border-slate-700` | Sidebar (`bg-slate-900`), task-tab container border-top (`border-slate-800`, matching `#memory-panel`/`#profile-panel`), individual task cards (`bg-slate-800`, matching `renderMemoryEntries` row styling) |
| Accent (10%) | `bg-indigo-600` / `hover:bg-indigo-500`, `focus:ring-indigo-500` | Reserved for exactly: the tab's own primary affordance if one exists (none needed — task creation is LLM-only, not a UI button per D-03/TASK-03), and the **Resume** button (`bg-indigo-600 hover:bg-indigo-500`) since resuming is the one positive/primary manual action a user takes on a task. Do not use indigo for Pause (neutral) or Cancel (destructive) — see below |
| Destructive | `bg-red-700 hover:bg-red-600` (button), `text-red-400` (inline error text) | Reserved for exactly: the **Cancel** button (matches the pre-existing destructive-button pattern at `app.js:564`, used for the context-overflow "delete message" action) and the `add-user-error`-style inline error text pattern if a task action fails |

Accent reserved for: the Resume button only, within the Task tab. Everything else in the tab (Pause button, task card backgrounds, state badges, timestamps) stays neutral slate to preserve the 60/30/10 balance — five task-state values rendering as five accent-colored badges would blow the 10% budget, so state is communicated via small text-color-only badges on a neutral `bg-slate-800` chip, not via saturated fills:

| Task state | Badge style |
|---|---|
| `planning` | `text-slate-400` on `bg-slate-800` chip (neutral/default — matches existing muted-label convention) |
| `execution` | `text-sky-400` on `bg-slate-800` chip (in-progress — distinct hue from the reserved indigo accent to avoid diluting it) |
| `validation` | `text-amber-400` on `bg-slate-800` chip (needs attention) |
| `done` | `text-emerald-400` on `bg-slate-800` chip (success — new hue for this phase, no prior precedent conflicts) |
| `cancelled` | `text-red-400` on `bg-slate-800` chip (matches existing `add-user-error` red) |
| paused overlay tag | `text-slate-500` chip with `⏸` glyph, shown alongside the state badge, never replacing it (D-04: pause is orthogonal to state) |

## Copywriting Contract

Voice: Russian, matching 100% of existing UI strings (`Память`, `Профиль`, `Настройки`, toast/error copy below). All new strings for this phase must be Russian, following the same terse, direct register as existing labels.

| Element | Copy |
|---------|------|
| Tab label | `Задачи` (mirrors `Память`/`Профиль` — single noun, no icon) |
| Panel heading | `Задачи` with a count badge next to it, e.g. `Задачи <span class="text-white font-semibold">3</span>` (mirrors `#memory-panel`'s count-badge pattern exactly) |
| Primary CTA (manual) | None — this phase has no user-facing "create task" button; task creation is LLM-tool-only per D-03/TASK-03. The only manual CTAs are per-task: **Продолжить** (Resume), **Пауза** (Pause), **Отменить** (Cancel) |
| Empty state heading | *(no separate heading — inline, matching `#memory-panel`'s minimal empty-state convention)* |
| Empty state body | `—` for "no tasks yet in this chat" (exact character used by `renderMemoryEntries`'s empty state at `app.js:265-268`) placed where the task list would render, optionally with one line of muted helper text below it: `Задачи появятся здесь, когда агент создаст новую` ("Tasks will appear here once the agent creates one") — optional per-task-list, required if the list is empty and the tab is opened for the first time in a chat |
| Error state | `Не удалось {действие}. Проверьте соединение и попробуйте снова.` — exact template already used by `saveProfile`'s failure toast (`app.js:337`). Concrete instances: `Не удалось загрузить задачи. Проверьте соединение и попробуйте снова.` (list load failure), `Не удалось поставить задачу на паузу. Проверьте соединение и попробуйте снова.` (pause failure), `Не удалось возобновить задачу. Проверьте соединение и попробуйте снова.` (resume failure), `Не удалось отменить задачу. Проверьте соединение и попробуйте снова.` (cancel failure) |
| Success toast | `Задача поставлена на паузу` / `Задача возобновлена` / `Задача отменена` — mirrors `saveProfile`'s success toast style (`Профиль сохранён`, `showToast(msg, 'success')`) |
| Destructive confirmation | Cancel: native `confirm()` dialog, matching the app's existing destructive-confirmation pattern (`app.js:971`, `Удалить этот чат?`) — exact copy: `Отменить эту задачу? Это действие нельзя отменить.` ("Cancel this task? This action cannot be undone.") Only Cancel needs confirmation; Pause and Resume are non-destructive and reversible, so they fire immediately on click with no dialog |
| Task history entry | Chronological line per transition, per D-11: `{from_state} → {to_state}` with timestamp and optional note, e.g. `planning → execution · 20.09.2026, 14:32` plus the note text below in muted color if present. State labels in the history line render in Russian: `планирование`, `выполнение`, `проверка`, `готово`, `отменено` |
