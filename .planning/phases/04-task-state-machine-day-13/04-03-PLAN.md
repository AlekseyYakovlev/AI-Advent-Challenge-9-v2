<objective>
Give the task lifecycle a pause button — both hands on it. The LLM can pause and resume a task it is working on, and the user can pause, resume or cancel any task directly from the sidebar without asking the model.

Purpose: TASK-04 ("a task can be paused at any state and resumed later") needs both control paths; D-12 requires the manual path to bypass the tool dispatcher while D-07 makes `cancelled` manual-only. RESEARCH Pattern 2 resolves the one genuinely new architectural question in this phase: bypassing the dispatcher is not license to bypass `agent/state.py::chat_locks`, because `Task` is chat-scoped (unlike the user-scoped `Profile` whose lock-free `PUT /api/v1/profile` is D-12's stated analog).
Output: `pause_task`/`resume_task` tools, `agent/tasks.py::set_paused`/`cancel_task`, `_get_task_or_404` plus three locked REST endpoints, and per-task Пауза / Продолжить / Отменить controls in the Задачи panel.

Pause and resume do NOT write `TaskTransition` rows (RESEARCH Pattern 4 / Assumption A1): `is_paused` is orthogonal to state (D-04), and TASK-05 asks for a history of *state* changes. Cancel DOES write one, because it is a real state change to the terminal `cancelled` value.
</objective>
