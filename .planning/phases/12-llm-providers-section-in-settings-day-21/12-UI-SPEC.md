# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Principle: this phase adds NO new visual language. The "Провайдеры LLM" section clones the existing "MCP серверы" section (`#mcp-section`, `ui/static/index.html` L317; `app.js` L1461+) and the model picker (`#model-select`) is extended in place. Source of each decision: CONTEXT.md (D-xx) or existing code.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla JS + Tailwind CDN; shadcn not applicable, no React/bundler per project constraints) |
| Preset | not applicable |
| Component library | none (hand-built DOM via `document.createElement` helpers, same as `mcpEl`) |
| Icon library | none (text/emoji glyphs only, as in existing UI: `✓`, `⚠️`, `&times;`) |
| Font | Tailwind default sans stack (no custom font; do not add one) |

Implementation rule: build rows with DOM APIs / `textContent` (never `innerHTML` with provider-supplied strings such as name, base URL, error messages, model ids). Any HTML insertion must pass `DOMPurify.sanitize()`.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between model-name and badge inside a row, `mt-1` helper text |
| sm | 8px | `gap-2` between buttons/title items, `space-y-2` between provider cards, `px-2` small buttons |
| md | 16px | `p-4` section/card/form padding, `space-y-4` form field vertical rhythm and section rhythm |
| lg | 24px | Not used inside the section |
| xl | 32px | Not used |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Layout (modeled on `#mcp-section` but deliberately using in-scale spacing, so it differs slightly from existing MCP markup): `<section id="llm-providers-section" class="border-t border-slate-700 p-4 space-y-4">`, placed directly after `#mcp-section` inside `#settings-modal` content. Header row `flex items-center justify-between`. Provider list container `#llm-provider-list` with `space-y-2`. Provider card `rounded-lg bg-slate-800 border border-slate-700 p-4 space-y-2`. Add/edit form `rounded-lg bg-slate-800/50 border border-slate-700 p-4 space-y-4`, hidden by default. Buttons and inputs use vertical padding `py-1` (4px, small buttons) or `py-2` (8px, inputs and primary buttons); never `py-1.5` or `py-0.5`.

Exceptions: none. Every spacing value in the new section must be on the scale (4, 8, 16, 24, 32, 48, 64); do not copy off-scale classes (`p-3`, `space-y-3`, `p-5`, `py-1.5`, `py-0.5`) from the existing `#mcp-section` markup, which is left untouched. Touch-target minimum is not raised (desktop-only, local tool).

## Typography

Only sizes/weights already used by the MCP section:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (form inputs, field labels, empty-state body, buttons) | 14px (`text-sm`) | 400 (primary buttons 600, see below) | 1.5 (Tailwind default for text-sm is 1.43; accept) |
| Label / meta (status badge, helper text, error text, small buttons, base URL line, picker group meta) | 12px (`text-xs`) | 400 | 1.33 (Tailwind default) |
| Heading (section title "Провайдеры LLM") | 18px (`text-lg`) | 600 (`font-semibold`) | 1.56 (Tailwind default) |
| Provider name in card / empty-state title | 14px (`text-sm`) | 600 (`font-semibold`) | 1.43 |

Display role: not used.
Weights: exactly two, 400 and 600, with no exceptions. The primary buttons "+ Добавить провайдера" and "Сохранить провайдера" use `font-semibold` (600); when copying classes from `#btn-mcp-add` / `#btn-mcp-save`, replace `font-medium` with `font-semibold`. `font-medium` (500) must not appear anywhere in the new section.

Visual anchor: the "+ Добавить провайдера" button (the only accent element in the section header) is the primary focal point, followed by provider names (600 weight). In the model picker, optgroup labels form the hierarchy level above model options.

Status indicator colors (reuse the MCP vocabulary verbatim, D-08): plain colored text, no pill background.

| State | Class | Label (RU) |
|-------|-------|-----------|
| not checked yet / disabled | `text-slate-400` | `не проверен` / `отключён` |
| checking | `text-sky-400` | `проверка…` |
| ok | `text-emerald-400` | `доступен · N моделей` |
| error | `text-red-400` | `ошибка` |

Define as `LLM_PROVIDER_STATUS_BADGE_CLASSES` / `LLM_PROVIDER_STATUS_LABELS` mirroring `MCP_STATUS_*` (or reuse the MCP maps by key mapping: not_checked->not_connected, checking->connecting, ok->connected, error->error). Warning text for a failing provider in the picker area uses existing yellow `text-yellow-500` (as `#stats-local-indicator`) and toasts use existing `showToast(msg, 'error' | 'success')`.

## Component Inventory and Interactions

### 1. Section "Провайдеры LLM" (Settings modal)
- Header: `h3.text-lg.font-semibold` "Провайдеры LLM" left; button `#btn-llm-provider-add` "+ Добавить провайдера" right (classes copied from `#btn-mcp-add`, with `font-medium` replaced by `font-semibold` and off-scale padding replaced by `px-4 py-2`).
- Order: header, hidden form `#llm-provider-form`, empty state `#llm-provider-empty`, list `#llm-provider-list`.

### 2. Provider card (one per provider; seeded DeepSeek and LM Studio appear as normal cards, D-03/D-05)
Header row (`flex flex-wrap items-center justify-between gap-2`):
- Left: name (`text-sm font-semibold truncate`) + status badge (`text-xs`, colors above).
- Right actions in this order: "Проверить" (neutral button `MCP_NEUTRAL_BTN_CLASSES`), "Изменить" (neutral), "Удалить" (red text button).
Second line (`text-xs text-slate-500`): `{base_url}` and, if key ref set, ` · ключ: {ENV_NAME}`; if empty ref, ` · без ключа`. Never display a key value (D-02; API never returns one).
When status is error: below, error block `text-xs text-red-400` with the classified message (see Copywriting). When ok: `text-xs text-slate-500` "N моделей" (no model list expansion in this phase).
Disabled provider: name gets `opacity-60`, badge shows "отключён", "Проверить" button disabled.
Buttons are `disabled` while that provider's check is in flight (`state.llmProviderChecking` Set, same as `mcpConnecting`).

### 3. Add/Edit form (`#llm-provider-form`, inline, not a modal)
Fields, each `label.block.text-sm.text-slate-400.mb-1` + input classes identical to `#mcp-name`:
1. `Название` (text, required)
2. `Base URL` (text, placeholder `https://api.deepseek.com`, required, must start with http:// or https://)
3. `Переменная окружения с API-ключом` (text, placeholder `DEEPSEEK_API_KEY`, `font-mono`, optional; helper `text-xs text-slate-500 mt-1`: "Имя переменной в .env, а не сам ключ. Оставьте пустым, если ключ не нужен.")
4. `Включён` checkbox (default checked)
Inline error `p#llm-provider-form-error.text-xs.text-red-400` (validation: empty name, invalid URL, invalid env-var name `^[A-Za-z_][A-Za-z0-9_]*$`, server 4xx detail).
Buttons right-aligned: "Отменить" (text button), "Сохранить провайдера" (accent, `font-semibold`). While saving: Save disabled, label "Сохранение…".

### 4. Save and check flow (D-08)
1. Click "Сохранить провайдера": POST/PUT; on success close form, re-render list, toast `Провайдер сохранён` (success).
2. Immediately and automatically run the check: badge switches to "проверка…" (sky), then to ok/error. No extra click required.
3. After the check settles, refresh the model picker (D-09).
4. "Проверить" button repeats step 2-3 manually.
5. Delete: browser `confirm()` (existing pattern in `onModelSelect`/MCP delete), then DELETE, re-render, refresh picker, toast `Провайдер удалён`.

### 5. Model picker (`#model-select`, header)
- Keep the existing single `<select>` (width `max-w-xs truncate`); use `<optgroup label="{Provider}">` per provider (D-10) containing `<option>` entries.
- Option text: `{Provider} · {model}` plus ` ✓` suffix for loaded LM Studio models (e.g. `DeepSeek · deepseek-chat`, `LM Studio · qwen2.5-7b ✓`). Prefix is repeated inside the option so the collapsed select still shows the provider.
- Option value encodes provider and model (planner picks encoding, e.g. `{provider_id}::{model}`); `state.selectedModel` and a new `state.selectedProviderId` must both be set before `trySendPending()`.
- Default selection order: previously selected (if still present) > first loaded LM Studio model > first entry overall (D-11 fallback).
- Disabled or unreachable providers: no optgroup at all (D-10). Unreachable provider produces one non-blocking toast per load `Провайдер «{name}» недоступен: {reason}` (type `error`), never blocks other providers.
- Empty (no providers produce models): single disabled option `Нет доступных моделей`. While loading: `Загрузка моделей…` (existing).
- LM Studio confirm-to-load (`confirm("Модель «X» не загружена. Загрузить?")`) is preserved and applies only to LM Studio entries; other providers' models select immediately with no confirm.
- If a chat/job references a deleted/disabled provider: show toast `Провайдер недоступен. Выбрана другая модель.` and fall back to first entry (D-11).

## Copywriting Contract

All UI labels Russian (D-12).

| Element | Copy |
|---------|------|
| Section heading | Провайдеры LLM |
| Primary CTA | + Добавить провайдера |
| Form save / cancel | Сохранить провайдера / Отменить |
| Manual check button | Проверить |
| Empty state heading | Провайдеры не настроены |
| Empty state body | Добавьте провайдера с OpenAI-совместимым API (DeepSeek, OpenAI, OpenRouter), чтобы его модели появились в списке выбора модели. |
| Check success | доступен · {N} моделей (badge); toast not needed |
| Error: bad key (401/403) | Неверный или отсутствующий API-ключ. Проверьте переменную {ENV_NAME} в .env и нажмите «Проверить». |
| Error: env var not set | Переменная {ENV_NAME} не найдена в .env. Добавьте её и перезапустите приложение. |
| Error: unreachable | Сервер недоступен. Проверьте Base URL и что сервис запущен. |
| Error: timeout | Превышено время ожидания ответа. Повторите проверку позже. |
| Error: other HTTP | Сервер вернул ошибку {status}. Проверьте Base URL (ожидается путь /v1/models). |
| Form validation | Укажите название. / Base URL должен начинаться с http:// или https://. / Недопустимое имя переменной окружения. |
| Saved / deleted toasts | Провайдер сохранён / Провайдер удалён |
| Destructive confirmation | Удалить провайдера: `Удалить провайдера «{name}»? Чаты и задачи, использующие его модели, перестанут работать, пока вы не выберете другую модель.` (native `confirm`) |
| Provider unavailable (chat/WS error) | Провайдер «{name}» недоступен. Выберите другую модель или проверьте настройки провайдера. |
| Scheduled run failure message | Провайдер недоступен (удалён или отключён) |

Destructive actions in this phase: delete provider only (confirm dialog above). Disabling is non-destructive and needs no confirmation.

## Accessibility and States

- All inputs have `<label for>`; status is text (not color alone: label text accompanies every color).
- Buttons are real `<button type="button">`; Enter in form inputs must not submit the outer `#settings-form` (form lives outside it, as with MCP).
- Focus ring on inputs: `focus:outline-none focus:ring-2 focus:ring-indigo-500`.
- Required states per provider card: not checked, checking, ok, error, disabled. Required list states: empty, populated. Required form states: add, edit, validation error, saving.
- Editing a seeded provider (DeepSeek / LM Studio) is allowed; no special badge needed.
