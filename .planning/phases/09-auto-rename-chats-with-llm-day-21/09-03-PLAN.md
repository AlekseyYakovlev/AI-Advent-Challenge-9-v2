## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> WS /ws/chat/{id} -> title job | The first user message (attacker-controllable text) flows into a second LLM call |
| title job -> /ws/events | A chat title leaves the process toward a user's sockets |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-13 | Spoofing (titling someone else's chat) | ws.py hook | high | mitigate | chat_id comes from the already ownership-checked socket (`_user_owns_chat` in `ws_chat`), user_id from `chat.user_id`; nothing client-supplied selects the chat or the recipient |
| T-09-14 | Information disclosure (cross-user frame) | hook -> hub | high | mitigate | Recipient = `chat.user_id`; e2e test asserts a second user's queue stays empty |
| T-09-15 | Tampering (prompt injection through the first message / answer) | title request | medium | mitigate | Request-shape test proves the call carries only TITLE_SYSTEM_PROMPT + tag-wrapped snippets, no tools key, no chat system prompt/memory; output passes `clean_title` (09-01) |
| T-09-16 | Denial of service (title call slows or breaks the turn) | hook placement | medium | mitigate | Sync `create_task` only, no await added to the turn; non-blocking test (done received while the call is blocked); 20 s timeout and no retry in 09-01 |
| T-09-17 | Denial of service (extra LLM call on every turn) | trigger rule | low | mitigate | Guard `title == 'New Chat' and parent_id is None`; tests for custom title, second turn and failed turn |
| T-09-18 | Tampering (legacy chat, user_id None) | hook | low | accept | Such chats cannot be opened over `/ws/chat` by a logged-in user (ownership check); if reached, 09-01 persists without publishing |
| T-09-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package is installed |
