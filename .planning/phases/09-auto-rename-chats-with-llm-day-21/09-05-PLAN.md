<objective>
Close the blocking verification gap of Phase 9: make the LLM title call produce a usable title on reasoning models, make an unusable answer visible in the log, bound the regex input of the title helpers (review CR-01), and correct the mislabeled UAT table of 09-04-SUMMARY.md.

Purpose: on the user's local model (`qwen/qwen3.5-9b`) the 30-token budget is spent entirely on reasoning, so every chat silently gets the fallback title; TITLE-01 is not met and nothing in the log shows it.

Chosen approach (planner decision, recorded here for the executor):
- Send `reasoning_effort: "none"` in the title request body and keep `max_tokens` 30 / `temperature` 0. Re-probed during planning against LM Studio `qwen/qwen3.5-9b` with the real prompt from `build_title_messages`: with the field -> HTTP 200, `finish_reason` `stop`, 7 completion tokens, 0 reasoning tokens, content `Настройка WebSocket в FastAPI`; without it -> `finish_reason` `length`, content `''`, 30 reasoning tokens. DeepSeek's API reference lists `reasoning_effort` with the value `none` (docs lookup, not a live call).
- Backend tolerance is not assumed: an HTTP 400 or 422 answer triggers exactly one repeat of the call without the field. Any other failure, or a second rejection, takes the existing fallback path. The whole ladder runs inside the existing single 20 s `asyncio.wait_for`, so the turn is never affected.
- Rejected alternatives: assistant prefill of an empty think block (template-specific), raising max_tokens to 2000+ (about 17x cost and latency, contradicts the "max_tokens ~30" wording of TITLE-02), parsing `reasoning_content` (unreliable). A backend that accepts the field but ignores it still gets the fallback title; that case is now logged as `chat_title_llm_unusable` and documented as a known limit.

Output: extended `agent/llm_client.py`, fixed `agent/titles.py`, new and updated tests, synced docs, corrected 09-04-SUMMARY.md, green full suite.
</objective>
