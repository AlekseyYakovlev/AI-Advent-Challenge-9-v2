Directly above `applySchedulerEvent` add `function applyChatTitleUpdate(frame)`: return when `frame` is falsy, `typeof frame.chat_id !== 'number'` or `typeof frame.title !== 'string'` or the title is empty after trim; find the chat with `state.chats.find((c) => c.id === frame.chat_id)`; when it is not in `state.chats` (created in another tab) call `loadChats().catch(() => {})` and return; otherwise set `chat.title = frame.title.slice(0, 200)`, call `renderChatList()`, and when `state.currentChatId === frame.chat_id` set `$('chat-title').textContent = chat.title`.     3. Below it add `function handleEventFrame(frame)`: when `frame && frame.type === 'chat_title_updated'` call `applyChatTitleUpdate(frame)` and return; otherwise call `applySchedulerEvent(frame)`. This check must come before `applySchedulerEvent`, whose first branch reloads scheduler tasks for ANY frame while `state.lastSchedulerTasks === null`.

    4. In `connectEventsWs()` -> `ws.onmessage` replace the call `applySchedulerEvent(frame);` with `handleEventFrame(frame);`. Leave `applySchedulerEvent` itself untouched.

    5. Reconnect recovery (decision: implemented, because frames are not replayed after a reconnect): add `async function refreshChatsAfterEventsReconnect()` that awaits `loadChats()` inside try/catch (swallow the error — the next reconnect or user action retries) and then, when `state.currentChatId` is set and that chat is found in `state.chats`, sets `$('chat-title').textContent` to its title. In `ws.onopen`, after the existing statements, add: when `state.eventsHasConnected` is true call `refreshChatsAfterEventsReconnect()`; then set `state.eventsHasConnected = true`. It must NOT run on the very first open: `init()` opens the socket before its own `loadChats()` / `createChat()`, and an extra concurrent list fetch there could resolve late and overwrite the list that contains the just-created chat.
