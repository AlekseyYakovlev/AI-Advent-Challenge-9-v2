<objective>
Give a ready knowledge base an "add files" flow in the browser: a button on the card, a compact modal reusing the pending-list controller, and card states for a running, finished and failed addition.

Purpose: the user-facing half of KBUP-05 and KBUP-06; keeping documentation current is the second half of the phase goal.
Output: `#kb-add-modal`, add-flow functions and card states in `ui/static/app.js`, a source-guard test, the modal close-policy guard extended to the new modal.

Decisions locked by this plan:
- "Addition running" is read from the server as `kb.status === 'ready' && kb.phase` (UI-SPEC section 5 left the mechanism to the planner; Plan 21-03 sets `phase` to `adding`). This also covers the page-load case, because `GET /api/v1/kb` returns `phase`.
- A failed addition is read as `kb.status === 'ready' && kb.error` with no running addition.
- The summary is kept in `state.kbAddSummary` (a `Map` keyed by kb id), not on the kb object, because `upsertKb` replaces the whole object on every frame. It clears on the next addition, on page reload or when the user clicks its `×`.
- The add modal closes only through its `×` button, like every other modal of the app. UI-SPEC interaction rule 7 says "Escape closes the add modal like the existing modals"; the existing modals do not close on Escape and `tests/test_modal_close_policy.py` forbids an Escape closer, so the phrase is implemented as "behaves like the existing modals": no Escape handler, no backdrop-click handler.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server events -> page | `kb_progress` frames carry the base name, error text and counts that become DOM text |
| page -> `POST /api/v1/kb/{kb_id}/files` | The page sends files for a base id held in client state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-28 | Tampering | XSS through a base name, a source name or a server error message shown in the modal title, the card lines or a toast | mitigate | Only `mcpEl` / `textContent` / `setAttribute` are used; `test_no_inner_html_in_add_code` forbids `innerHTML` in the add-flow functions |
| T-21-29 | Elevation of Privilege | A tampered `state.kbAddTargetId` pointing at another user's base | accept | The id is only a request parameter; the server answers 404 for a foreign base (Plan 21-04, `test_add_files_to_foreign_kb_returns_404`) |
| T-21-30 | Spoofing | Add request sent from another origin | mitigate | Server-side `require_allowed_origin` (Plan 21-04); the page sends `credentials: 'include'` from the app origin only |
| T-21-31 | Denial of Service | Double submit starting two additions | mitigate | Submit button disabled while the request is in flight; the add button is disabled while `phase` is set; the server claim rejects a second addition with 409 |
| T-21-32 | Tampering | Modal closed by backdrop click or Escape losing the pending list unexpectedly | mitigate | No overlay or key listener; `tests/test_modal_close_policy.py` covers `kb-add-modal` |
| T-21-SC | Tampering | Package installs | accept | No packages or CDN libraries are added |
