<objective>
Move knowledge-base document identity from the content hash to the source name, keep relative paths as source names on the server, raise the file-count limit to a named constant and expose all upload limits through one endpoint.

Purpose: KBUP-03 needs `docs/a/README.md` and `docs/b/README.md` to be two sources; today the server reduces every name to its base name and a table-level UNIQUE (`kb_id`, `sha256`) rejects identical content under two names. KBUP-04 needs a higher, named, single-source limit.
Output: schema change plus a start-up migration that preserves chunks, a server-authoritative source-name sanitiser, `GET /api/v1/kb/limits`, updated and new tests.

Decisions locked by this plan (Claude's Discretion in CONTEXT.md / open questions of RESEARCH.md):
- Uniqueness of (`kb_id`, `filename`) is enforced in code only. The table gets a plain (non-unique) composite index `ix_kbdocument_kb_filename`, because legacy bases may already hold duplicate file names.
- `MAX_FILES = 200`. `MAX_SOURCE_NAME_CHARS = 300` (below the 500-character `file` query cap of `agent/rag_api.py`).
- Source names are compared exactly and case-sensitively after NFC normalisation.
- `sha256` stays as a column and is used only for change detection (Plan 21-04).
</objective>
