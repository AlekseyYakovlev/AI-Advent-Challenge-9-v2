Behaviour to document (as built by Plans 21-01 .. 21-06; confirm every statement against the code before writing it):
- `GET /api/v1/kb/limits` -> `{"max_files", "max_file_bytes", "max_total_bytes", "max_source_name_chars", "extensions"}`; session only.
- `POST /api/v1/kb`: multipart `filename` of each part is the source name; sanitised on the server (NFC, `\` -> `/`, control characters removed, empty / `.` / `..` / drive segments dropped, at most `MAX_SOURCE_NAME_CHARS` characters); duplicate means the same source name twice in one request; identical content under different names is accepted; up to `MAX_FILES` files.
- `POST /api/v1/kb/{kb_id}/files`: multipart `files` only; `202` + `KbOut` with `status: "ready"`, `phase: "adding"`; `404`, `409` (`MSG_ADD_NOT_READY`, `MSG_ADD_BUSY`), `413`, `422`; classification added / replaced / unchanged by source name and SHA-256.
- `KbOut.phase` may be `adding` while `status` is `ready`; `KbOut.error` may be set on a ready base after a failed addition.
- Final `kb_progress` frame of an addition carries `add_summary: {added, replaced, unchanged}`.
- Tables: `KbDocument` has no unique constraint; non-unique index `ix_kbdocument_kb_filename`; start-up migration `migrate_kbdocument_drop_sha_unique`.
- Storage: stored files are named `uuid4().hex + extension`; per-request staging under `uploads/_staging/<uuid>/`.
- Orphan recovery: a ready base left with a `phase` gets `phase` cleared and a restart message.

Harness of `scripts/e2e_kb_playwright.py` that the new script reuses: constants `UI_PORT = 18000`, `AGENT_PORT = 18001`, `UI_URL`, `AGENT_URL`, `LM_URL`, `NOMIC`, `STEP_TIMEOUT_MS`; `report(label, passed, detail)`, `checks`, `page_errors`, `port_is_free(port)`, `prepare_copy(scratch) -> Path` (copies the tree without `docs`, `scripts`, `tests`, `.planning`, patches the copy to the isolated ports), `seed_scratch_users(db_path, users) -> dict[str, int]`, `wait_for_app(client)`, `login(page, username, password)`, `open_modal(page)` (waits for the embedding-model default, so it needs LM Studio), `kb_row(page, name)`, `row_text(page, name)`, `wait_row(page, name, needle, timeout)`, `run_search(page, name, query)`, `close_search(page)`, `teardown(app_proc)`.
