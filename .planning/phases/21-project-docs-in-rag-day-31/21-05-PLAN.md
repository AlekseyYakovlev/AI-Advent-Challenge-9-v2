<objective>
Rebuild the file section of the "new knowledge base" form: a second control that picks a whole folder, an accumulating pending list with relative paths, a folder report with taken/skipped counts, limits shown from the server, and upload of every file under its source name.

Purpose: KBUP-01, KBUP-02, the browser half of KBUP-03 and KBUP-04. Without the third argument of `FormData.append` the server only ever sees base names.
Output: changed `#kb-create-modal` markup, one reusable pending-list controller in `ui/static/app.js` (Plan 21-06 creates a second instance for the add modal), a source-guard test.

Decisions locked by this plan (Claude's Discretion: layout; UI-SPEC planner decision: delivery of limits):
- Limits reach the page through `GET /api/v1/kb/limits` (Plan 21-01), stored in `state.kbLimits`. Until they are loaded the helper line shows no numbers and submit is disabled; the front end has no fallback numbers.
- The extension filter also comes from `state.kbLimits.extensions`, so the list of supported types has one source.
- One controller factory `createKbPending(ids, options)` serves both modals (RESEARCH Pitfall 12).

Interpretation of KBUP-03 / roadmap success criterion 3 (planner's reading, not a user decision; RESEARCH Open Question 3, RESOLVED):
- The requirement says the relative path is the source name "in the knowledge base file list, in search results and in answer sources". The app has no per-base document list (no route returns a base's files and the card shows only a file count), and this phase does not add one.
- "The knowledge base file list" is therefore delivered as the pending list of the create form (this plan) and of the add modal (Plan 21-06), where every entry shows its relative-path source name. Search results and answer sources show the same names; the names actually stored are checked in the database by Plan 21-07 (check B2).
- Do NOT add a documents endpoint, a document list on the card or any other per-base listing: that is new scope. If the user expects such a list, it is a follow-up phase.
</objective>
