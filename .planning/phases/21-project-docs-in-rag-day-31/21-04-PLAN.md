<objective>
Add the route that accepts files for an existing ready knowledge base, validates and stages them, classifies each file as added, replaced or unchanged by source name and content hash, claims the base atomically and starts the addition job.

Purpose: KBUP-05 (add to a ready base), KBUP-06 (replace by source name), KBUP-04 (limits rejected with nothing stored) on the server side.
Output: `POST /api/v1/kb/{kb_id}/files` in `agent/kb_api.py` and its tests.

Decisions locked by this plan:
- Classification rule: existing documents are grouped by `filename`. No group -> added. A group of exactly one document whose `sha256` equals the uploaded file's -> unchanged (staged file deleted). Any other non-empty group -> replaced, and every document of the group is superseded (this also collapses duplicate file names that legacy bases may hold).
- Legacy bases keep base-name sources; `docs/API_SPEC.md` does not match a legacy `API_SPEC.md` and is added as a new source.
- The hash is taken over the raw bytes; a file with different line endings counts as changed.
- Limits apply per upload request (D-16), not to the accumulated size of the base.
- The summary reaches the client in the final `kb_progress` frame (`add_summary`); the 202 response body is `KbOut` like the create route.
</objective>
