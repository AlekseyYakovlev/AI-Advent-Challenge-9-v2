<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public GitHub repository -> self-hosted runner on the user's PC | Anyone can open a PR; the runner executes workflow code locally |
| GitHub secret store -> runner job | Holds the app's API key |
| local branch -> public remote | Pushing publishes commits |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-58 | Elevation of privilege | Fork PR executing code on the user's machine through the self-hosted runner on a public repository (severity high) | mitigate | Blocking user decision (Task 1) with the residual risk spelled out and the private-repository and ephemeral options; required settings in Task 2 step 3 (approval for all external contributors, read-only default token); unique label `pr-review`; runner started interactively only for the demo, never as a service; same-repository condition and no `pull_request_target` in the workflow; event data only through `env:`; action pinned by SHA |
| T-24-59 | Elevation of privilege | Residual risk after mitigations (approval bypass after a merged contribution, mistaken approval) | accept | Accepted only by the user's explicit choice in Task 1, recorded in 24-CHECKS.md; the docs tell the user to keep the runner offline when idle; `private-repo` and `no-runner` remain available |
| T-24-60 | Information disclosure | API key leaving through the secret (same-repository PR editing the workflow) | mitigate | Dedicated key `github-actions-review`, loopback-only app, revocation and rotation after the demo (user guide); only the owner can write to the repository |
| T-24-61 | Information disclosure | Secrets written into 24-CHECKS.md, commits or logs | mitigate | Grep gate on the checks file; the control script scrubs secrets; environment variables are set by the user and never echoed |
| T-24-62 | Tampering | Push overwriting remote history or publishing foreign uncommitted work | mitigate | Plain `git push -u origin Day32`, never `--force`; clean-tree precondition; `main` untouched |
| T-24-63 | Information disclosure | Publishing unpublished Day 31 commits | mitigate | Explicit push consent (`push Day32: yes` / `no`) in the Task 1 decision, recorded in 24-CHECKS.md; Task 3 and Plans 24-13, 24-14 push only when the recorded answer is yes; `.env` is ignored by git |
| T-24-64 | Denial of service | First review timing out while the code index of `Day32` is built | mitigate | 60-minute job timeout, 55-minute client timeout, 60-minute wait; the outcome is recorded either way |
| T-24-SC | Tampering | package installs | accept | No package is added; the runner binary is downloaded by the user from GitHub's own page |
</threat_model>
