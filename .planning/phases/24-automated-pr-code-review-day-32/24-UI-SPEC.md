# Phase 24 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope of this contract

Phase 24 is mostly a backend and CI phase. CONTEXT.md (D-03, D-12, D-13) places the review output in a GitHub PR comment, and the Action prints errors in the job summary (D-04). Only a small in-app surface is called for. The contract therefore covers three user-facing surfaces and nothing else.

| # | Surface | Source decision | Contract below |
|---|---------|-----------------|----------------|
| S1 | New "Review settings" section in the Settings window, placed after "MCP серверы" and "Провайдеры LLM" (or next to "MCP серверы"; planner picks the exact slot) | D-05, D-07, D-08, D-09, Claude's Discretion (settings location) | Full contract (spacing, type, color, copy) |
| S2 | PR comment and job summary text (Markdown rendered by GitHub, not by the app) | D-12, D-13, D-14, D-15 | Text structure and copy contract only. GitHub controls the visuals. |
| S3 | Action job error output (plain log lines and job summary) | D-04 | Copy contract for error reasons only |

Explicitly out of scope: any chat-window change, a `/review` command, an in-app review viewer or history list (Claude's Discretion item "stored and visible inside the app" is resolved here as NOT built in this phase, assumption A1), inline diff comments, and any change to the browser upload form (D-07).

## Spacing Scale

Declared values (multiples of 4). The Settings window already uses Tailwind defaults, which all fall on this scale. New markup must use only these.

| Token | Value | Tailwind | Usage in S1 |
|-------|-------|----------|-------------|
| xs | 4px | `mb-1`, `mt-1` | Label-to-input gap, helper text offset |
| sm | 8px | `gap-2`, `py-2` | Button row gap, input vertical padding |
| md | 16px | `p-4`, `space-y-4` | Form container padding, field stack |
| lg | 24px | `p-6` | Not used inside the section; reserved for modal padding already present |
| xl | 32px | none | Not used |
| 2xl | 48px | none | Not used |
| 3xl | 64px | none | Not used |

Exception: 12px (`px-3`) for input horizontal padding only, kept for consistency with the sibling inputs in `#mcp-section` and `#llm-providers-section`. It is a multiple of 4. The section container uses `p-4` (16px) like `#llm-providers-section`; no 20px exception is used.

## Typography

Exactly the sizes already in the Settings window.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (inputs, buttons, list rows) | 14px (`text-sm`) | 400 regular (buttons 600) | 1.5 |
| Label (field labels) | 14px (`text-sm`, `text-slate-400`) | 400 | 1.5 |
| Helper / status text | 12px (`text-xs`) | 400 | 1.5 |
| Heading (section title, `h3`) | 18px (`text-lg`) | 600 semibold | 1.2 |
| Display | not used in this phase | not applicable | not applicable |

Weights declared: 400 and 600 only. Primary buttons in the new section use `font-semibold` (as `#llm-providers-section` does) instead of `font-medium`, so no third weight is introduced. Field labels use 14px regular (same size as Body, so the scale stays at three sizes: 14, 12, 18) in `text-slate-400`, matching existing `<label class="block text-sm text-slate-400 mb-1">`. Paths, branch names, model ids use `font-mono`.

## S1 — Review settings section: layout and interaction

Container: `<section id="review-settings-section" class="border-t border-slate-700 p-4 space-y-4">`, heading `<h3 class="text-lg font-semibold">Ревью Pull Request</h3>`. The section is a plain form (no add/list pattern), because review settings are one row per user.

Fields, top to bottom (each is `label.block.text-sm.text-slate-400.mb-1` + control + optional `p.text-xs.text-slate-500.mt-1`):

| Field | Control | Notes |
|-------|---------|-------|
| Путь к репозиторию | text input, `font-mono` | Absolute path to the local git repository (D-07). Helper: "Папка с git-репозиторием проекта. Индексируются файлы, отслеживаемые git." |
| База документации | `select` of the user's ready knowledge bases | D-08. First option "Не выбрана". |
| Провайдер | `select` of enabled LLM providers | D-05. Default selection: the local LM Studio provider. |
| Модель | `select` or text input populated for the chosen provider | D-05. Default: the local LM Studio model. |
| Состояние индекса кода | read-only status line (`text-xs text-slate-400`) | Shows "Не построен" or "Обновлён: {время}, файлов: {N}". Updated after refresh. |

Buttons row (`flex justify-end gap-2 pt-2`): "Обновить индекс кода" (secondary style: `text-slate-400 hover:text-white`; no accent), "Сохранить настройки ревью" (accent, `font-semibold`).

States:
- Loading: refresh button disabled, label changes to "Индексация…", status line shows "Идёт индексация". Save stays enabled.
- Success: status line shows the new timestamp and file count in `text-slate-400`.
- Error: `p.text-xs.text-red-400` under the buttons, built with `textContent`. Inputs keep their values.
- Empty (no repo path saved): status line reads "Не построен", refresh button disabled with helper "Сначала укажите путь и сохраните настройки."
- Validation: path must be non-empty and the server returns 400/422 with a readable detail when the folder is not a git repository; show that detail verbatim in the error line.
- Accessibility: every control has a `<label for>`; the error and status lines use `aria-live="polite"`; focus order follows visual order; all controls reachable by keyboard; touch targets for buttons are at least 32px high (`py-2` + 14px text with 1.5 line height gives 36px).
- No confirmation dialogs: nothing destructive. Refresh is idempotent (D-09: re-indexes only changed files by content hash).

Focal point: the primary visual anchor of S1 is the accent-filled "Сохранить настройки ревью" button at the bottom right of the section; it is the only indigo-filled element, so it draws the eye first. Within the form, the 18px semibold heading "Ревью Pull Request" is the entry point, and the index status line (12px, slate-400) is deliberately quiet.

Responsive: the Settings modal already constrains width; fields are `w-full`, so no breakpoint-specific rules are added.

### S2 — PR comment contract (Markdown, Russian)

Structure, in this order, exactly one comment per PR (D-13, D-14):

1. First line: hidden marker `<!-- ai-pr-review -->` (for replacement, D-14); not visible.
2. Title line: `## Ревью Pull Request` followed by a line `Коммит: {короткий sha}` and `Модель: {provider/model}`.
3. `### Потенциальные баги`
4. `### Архитектурные проблемы`
5. `### Рекомендации`
6. `<details><summary>Источники</summary>` with two bullet lists, "Документация" and "Код" (D-08), each item as `path` or `path:start-end` (D-11). Assumption A2: sources are listed, collapsed by default.

Focal point (S2): the three `###` headings are the only scan anchors in the comment; remark bullets are plain text and "Замечаний нет." is plain text with no emphasis. The title line is the first thing read; the collapsed Sources block is the lowest-priority element.

Rules: each remark is one bullet that names `` `file.py:123` `` in text and states problem then suggestion. Assumption A3: no severity labels in this phase (keeps three sections as the only structure). An empty section contains the line "Замечаний нет." rather than being omitted, so a clean PR is distinguishable from a failed review. Comment must stay under GitHub's 65 536-character limit; the caller script truncates the Sources block first, never the three sections.

### S3 — Job error and summary contract

The caller script prints one line per failure to the job summary and exits non-zero (D-04). Reason texts (Russian, one per cause):

| Cause | Summary line |
|-------|--------------|
| App not reachable | Ревью не выполнено: приложение недоступно по адресу {url}. Проверьте, что приложение запущено и адрес указан верно. |
| API key rejected | Ревью не выполнено: ключ API отклонён. Проверьте секрет репозитория с ключом API и совпадение с ключом в приложении. |
| GitHub MCP not configured or not connected | Ревью не выполнено: сервер GitHub не настроен или не подключён. Подключите сервер `github-mcp-server` в настройках «MCP серверы» и повторите. |
| LM Studio down (embeddings or generation) | Ревью не выполнено: LM Studio недоступен. Запустите LM Studio, загрузите модель и перезапустите задачу. |
| Model failure | Ревью не выполнено: модель вернула ошибку: {кратко}. Проверьте провайдера и модель в настройках «Ревью Pull Request» и перезапустите задачу. |

The API key and token values are never printed; lines name the secret only generically (no value, no invented secret name).
