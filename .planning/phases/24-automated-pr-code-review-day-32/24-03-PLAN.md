## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app -> github-mcp-server (stdio subprocess) | Carries the user's GitHub token in the subprocess environment |
| GitHub -> app | PR title, body, file names and diff are attacker-controlled text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-06 | Information disclosure | Token or diff in logs and in 24-CHECKS.md | mitigate | Log method names and sizes only; CHECKS file records keys and lengths only; a grep gate rejects token prefixes |
| T-24-07 | Tampering | Silent partial diff (20 000-character cut) | mitigate | Direct `session.call_tool`; test with a 300 000-character diff; source gate forbids `call_mcp_tool` in this module |
| T-24-08 | Denial of service | PR with thousands of files | mitigate | `MAX_FILE_PAGES = 30` and `PR_TOO_LARGE`; per-call timeout `REVIEW_MCP_TIMEOUT` |
| T-24-09 | Elevation of privilege | Using another user's GitHub server row | mitigate | Rows resolved only through `mcp_config` filtered by the API key's `user_id` |
| T-24-10 | Elevation of privilege | Over-privileged token (Contents write) | accept | The server runs `--read-only` (no write tools, verified in 22-CHECKS); a read-only token is recommended in the docs of Plan 24-09 |
| T-24-11 | Spoofing | Wrong repository through a crafted `repo` string | mitigate | `repo` validated by regex before any call; the repository is cross-checked against the local remote in Plan 24-05 |
| T-24-SC | Tampering | package installs | accept | No package is added |
</threat_model>
