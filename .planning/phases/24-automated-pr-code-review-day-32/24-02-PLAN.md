  <action>
    Create `agent/code_chunking.py` with module docstring "Split source files into fragments for the code knowledge base." Pure functions only: no I/O, no logging of file content, no imports from `agent.kb_indexer`. Import `ChunkDraft` from `agent.kb_chunking`.

    `chunk_code` dispatches on the lower-cased suffix: `.py` goes to `chunk_python`, everything else to `chunk_lines`. `chunk_python` calls `ast.parse(text)` and catches `SyntaxError`, `ValueError` and `RecursionError`, falling back to `chunk_lines`. It walks `tree.body` only: for `FunctionDef` and `AsyncFunctionDef` the start line is the smallest `lineno` among the node and its `decorator_list`, the end is `end_lineno`; for `ClassDef` one fragment covers the class start up to the line before its first method (or the whole class when it has no methods) and each method (direct child function of the class) is its own fragment named `Class.method`; class-level statements between methods stay with the preceding fragment. Lines of the module that belong to no definition (imports, constants, code between definitions) are grouped into `<module>` fragments in source order; whitespace-only groups are dropped. Slice by lines only; never use `col_offset` or `end_col_offset` (they are UTF-8 byte offsets, the code base has Cyrillic strings).

    One private helper builds fragments for a named line span and enforces the cap: the header line plus the body must not exceed `MAX_CHUNK_CHARS`; a longer span is cut on line boundaries into consecutive parts (each with its own `L{start}-{end}` range and the same name), and a single line that alone exceeds the remaining room is cut by characters. `chunk_lines` uses that helper over windows of `WINDOW_LINES` lines advancing by `WINDOW_LINES - WINDOW_OVERLAP_LINES`. `parse_line_range` uses one compiled pattern matching `L(\d+)-(\d+)` at the end of the section string (optionally inside parentheses).
