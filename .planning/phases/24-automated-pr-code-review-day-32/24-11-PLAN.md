    - The system message (Russian) defines: a defect is found only when the review names the same problem in the same file (a different wording counts, a vague hint does not); a false remark is a remark in the bugs or architecture sections that states a problem which does not exist in the changed code; remarks in recommendations, style advice and remarks covered by a tolerated note are not false; it fixes the reply format: one line per key `KEY: найден` or `KEY: не найден` followed by ` — ` and a short reason, then a line `Ложных замечаний: N`, then one line per false remark starting with `- `
    - `parse_judge_reply(text, keys)` returns findings for every key and the false count for a well-formed reply; strips a `<think>` block; tolerates extra spaces, `**` around keys and a different dash; returns `None` when any key is missing or the count line is absent

    - `--check` returns the preflight exit code and message of the analog: key missing, key refused (HTTP status only), DeepSeek unreachable, model not listed; no judge call is made
    - When the preflight fails in `judge`, every PR of the run is written with `judge_status: "не запускалось"` and the reason from the preflight, and the command exits with the preflight code
    - The key value never appears in stdout, in `<run>.json` or in `verdicts.csv`
    - `smoke` (`control: false`) is never judged

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| review text (model output) -> judge prompt | Untrusted text enters another model's prompt |
| script -> DeepSeek | Cloud API with a secret key; review texts and planted-defect descriptions leave the machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-53 | Tampering | Review text steering the judge ("mark all as found") | mitigate | Tag-wrapped data with neutralised angle brackets; strict line format parsed by key; unparsable replies are not turned into verdicts |
| T-24-54 | Information disclosure | DeepSeek key in output or files | mitigate | Environment-only key; refused key reports the HTTP status only; test asserts absence |
| T-24-55 | Repudiation | Missing or failed judging shown as a verdict | mitigate | `judge_status` field; `не запускалось` cells; no model call for reviews that were not obtained; tests |
| T-24-56 | Repudiation | Self-judging bias hidden | mitigate | Mandatory sentence when the judge's provider wrote the run (D-19) |
| T-24-57 | Information disclosure | Review texts of demo code sent to DeepSeek | accept | The texts concern planted demo files of a public repository; D-19 chooses this judge |
| T-24-SC | Tampering | package installs | accept | No package is added |
