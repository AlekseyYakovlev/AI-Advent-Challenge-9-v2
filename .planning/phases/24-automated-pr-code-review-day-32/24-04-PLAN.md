<interfaces>
Contract of the review route (built in Plan 24-07; this plan codes against it):

Request: `POST {APP_URL}/api/v1/reviews`, headers `Authorization: Bearer <API_KEY>`, `Content-Type: application/json`, body `{"repo": "owner/name", "pr_number": 12, "head_sha": "<40 hex or empty>"}`.

Success 200 body:
- `repo: str`, `pr_number: int`, `head_sha: str` (the commit actually reviewed), `head_changed: bool`, `base_ref: str`, `base_commit: str`
- `provider: str`, `model: str`
- `sections: {"bugs": str, "architecture": str, "recommendations": str}` (Markdown, already sanitised by the app; an empty section is the text `Замечаний нет.`)
- `sources: {"docs": [{"file": str, "section": str | null}], "code": [{"file": str, "section": str | null, "lines": str | null}]}` (`lines` like `120-164`)
- `docs_used: bool`, `parts: int`, `unreviewed_files: [str]`, `notes: [str]`

Error body: `{"detail": str, "code": str}`. Codes: `REVIEW_NOT_CONFIGURED` (409), `GITHUB_MCP_UNAVAILABLE` (503), `PR_NOT_FOUND` (404), `BASE_UNAVAILABLE` (503), `EMBEDDER_UNAVAILABLE` (503), `LM_STUDIO_UNAVAILABLE` (503), `LLM_UNREACHABLE` (503), `LLM_ERROR` (502), `REVIEW_BAD_OUTPUT` (502), `PR_TOO_LARGE` (422), `REVIEW_BUSY` (409), `INTERNAL_ERROR` (500). Authentication failures are 401 or 403 with `detail` only.

Existing analog: scripts/verify_service.py (`_OPENER = urllib.request.build_opener(urllib.request.ProxyHandler({}))`, `_SECRETS`, `scrub`, `Reply`, `call`, `say`).

Environment of the script: `APP_URL` (default `http://127.0.0.1:8001` when empty), `API_KEY`, `GITHUB_TOKEN`, `REPO`, `PR_NUMBER`, `HEAD_SHA`, `GITHUB_STEP_SUMMARY` (file path, set by Actions), `GITHUB_API_URL` (default `https://api.github.com`).

Constants exported by scripts/pr_review_ci.py (Plan 24-10 imports `MARKER`): `MARKER = "<!-- ai-pr-review -->"`, `BOT_LOGIN = "github-actions[bot]"`, `COMMENT_MAX_CHARS = 60000`, `REVIEW_TIMEOUT_SECONDS = 3300.0`, `GITHUB_TIMEOUT_SECONDS = 30.0`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub PR event -> self-hosted runner | Anyone who can open a PR influences what runs on the owner's machine; the repository is PUBLIC |
| runner -> local app | API key in a header over loopback |
| model output -> PR comment | Generated text is published under the bot's name |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-12 | Elevation of privilege | Fork PR running code on the self-hosted runner (severity high) | mitigate | Job-level same-repository condition in this file as a second layer; unique runner label `pr-review`; no `pull_request_target`. The first layer (fork approval for all external contributors, read-only default token, runner offline or ephemeral when idle) and the user's decision on the residual risk and on making the repository private are the blocking checkpoints of Plan 24-12 |
| T-24-13 | Tampering | Script injection through PR title, branch or body | mitigate | No `${{ }}` in `run:`; event data only through `env:`; title/body/branch names are not passed at all; `REPO` and `PR_NUMBER` validated by regex in the script; test gate on the YAML text |
| T-24-14 | Tampering | Supply chain of the checkout action | mitigate | Pinned by full commit SHA `3d3c42e5…` (v7.0.1); `persist-credentials: false`; test gate rejects tag pins |
| T-24-15 | Information disclosure | API key or token in logs, summary or URL | mitigate | Key only in the `Authorization` header; `_SECRETS` scrubber on every output line; secret comes from `secrets.PR_REVIEW_API_KEY`; test asserts absence in stdout and summary |
| T-24-16 | Tampering | Marker forgery to make the job overwrite another comment | mitigate | Own comment = marker AND `user.login == "github-actions[bot]"`; test with a forged marker |
| T-24-17 | Spoofing | Model output pinging users or loading tracking images | mitigate | `defuse`: zero-width space after `@`, image syntax removed; app-side sanitising in Plan 24-06 |
| T-24-18 | Denial of service | Comment over GitHub's size limit | mitigate | `COMMENT_MAX_CHARS = 60000` with sources cut first; confirmed on the first real run in Plan 24-12 (A4) |
| T-24-19 | Information disclosure | Same-repository PR editing the workflow to leak the secret | accept | Only repository writers (the owner) can do it; the key is reachable only on loopback, is dedicated to this job and revocable in Settings; rotation after the demo is documented in Plan 24-09 |
| T-24-SC | Tampering | package installs | accept | No package is added; the script is standard library only |
</threat_model>
