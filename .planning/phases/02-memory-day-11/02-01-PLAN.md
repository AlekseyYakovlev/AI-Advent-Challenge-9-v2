- `list_working_memory(session: AsyncSession, chat_id: int) -> list[WorkingMemory]` — `select(WorkingMemory).where(WorkingMemory.chat_id == chat_id).order_by(WorkingMemory.key)`, returns `result.all()`.

- `save_working_memory(session: AsyncSession, user_id: int, chat_id: int, key: str, value: str) -> WorkingMemory` — upsert: SELECT by `(chat_id, key)`; if found, set `.value` and `.updated_at = datetime.now(timezone.utc)`; else insert a new row. Catch `sqlalchemy.exc.IntegrityError` specifically on the insert path (the UniqueConstraint can lose a race) and retry once as an update rather than propagating. `await session.refresh(row)` before returning. Log `logger.info("working_memory_saved", chat_id=..., key=...)`.
- `save_long_term_memory(session: AsyncSession, user_id: int, key: str, value: str) -> LongTermMemory` — same upsert shape keyed on `(user_id, key)`, preserving `created_at` on update and bumping `updated_at`.

All four take the caller's `session` and never open their own — the tool dispatcher (Plan 03) must be able to run them inside `agent/ws.py`'s already-open per-chat-locked session. ## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `get_chat_memory` | mitigate | Call `_get_chat_or_404(session, chat_id, current_user.id)` before any memory query; return 404 (never 403) for non-owned chats — test (e) in `tests/test_memory_api.py` |
| T-02-02 | Elevation of Privilege | long-term memory query | mitigate | `user_id` is derived exclusively from `current_user.id`; no query param or body field can set it — asserted by grep gate in Task 2 |
| T-02-03 | Tampering (XSS) | `renderMemoryPanel` | mitigate | Every memory `key`/`value` inserted via `document.createElement` + `textContent`; no `innerHTML` assignment added — asserted by grep gate in Task 3 |
| T-02-04 | Denial of Service | unbounded memory growth | accept | `max_length=200` / `50_000` caps per row; row-count cap deferred — MVP scope, single-user local app, logged via structlog for observability |
| T-02-05 | Information Disclosure | cross-user long-term memory | mitigate | `UniqueConstraint("user_id", "key")` plus `user_id`-filtered queries; test (d) in `tests/test_memory.py` proves two users' identical keys stay independent |
| T-02-SC | Tampering | npm/pip installs | mitigate | Not applicable — this phase installs zero new packages (02-RESEARCH.md Package Legitimacy Audit); no install task exists in this plan |
</threat_model>
