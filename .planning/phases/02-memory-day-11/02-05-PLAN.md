  <what-built>
Three explicitly separated memory layers with tool-call-only writes and an always-visible inspection panel:
- `WorkingMemory` (per chat) and `LongTermMemory` (per user, cross-chat) SQLite tables, independent of the message tree.
- `agent/tools.py` — a registry + strictly sequential dispatcher that is the only path to a memory write, running inside the existing per-chat lock and DB session.
- Two separately named tools, `save_working_memory(key, content)` and `save_long_term_memory(key, content)`.
- Read-only injection of both layers into the system prompt on every turn.
- `GET /api/v1/chats/{chat_id}/memory` and the sidebar `Память` panel showing all three layers.
- LM Studio model load/unload migrated to the working v1 control endpoints.
  </what-built>
  <how-to-verify>
1. Start the app (`python run.py`), open `http://localhost:8000`, log in, and make sure the tool-capable model from Task 1 is selected.
2. Create a new chat. Confirm the sidebar shows the `Память` panel with three labelled layers and all counts at zero except short-term.
3. Send: `Запомни навсегда, что меня зовут Alex. И отметь для этого чата, что текущий шаг — черновик введения.`
   Expect: the reply confirms both saves, the `Память` panel refreshes automatically when the turn finishes, `Рабочая (этот чат)` shows one entry (something like `current_task_step` → `черновик введения`), and `Долговременная (все чаты)` shows one entry (`user_name` → `Alex`).
   Check the agent console: there must be two `tool_call_dispatched` log lines with distinct `tool_call_id` values. **If the reply claims a save but no log line and no panel row appeared, that is a failure** — prose is never evidence of a write.
4. Send a second message in the same chat: `Какой у меня текущий шаг?` Expect the agent to answer from working memory without being re-told.
5. Create a SECOND chat. Confirm `Долговременная (все чаты)` still shows `Alex` (long-term is user-scoped, D-02) while `Рабочая (этот чат)` is empty (working memory is per chat, D-03).
6. In the second chat ask: `Как меня зовут?` Expect `Alex`, answered purely from injected long-term memory.
7. Send an ordinary message with nothing worth remembering (e.g. `Спасибо!`). Expect NO new rows in either layer and no `tool_call_dispatched` line — writes happen only on explicit tool calls, never automatically (MEM-03).
8. Delete the first chat. Expect its working-memory entry to disappear while the long-term `Alex` entry survives.
  </how-to-verify>
