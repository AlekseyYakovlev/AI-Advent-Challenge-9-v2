# Phase 17 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This phase adds NO new design system. It reuses the tokens already in `ui/static/index.html` / `app.js` (Tailwind CDN utility classes, slate dark theme). Every value below was read from the existing code (memory panel `#memory-panel`, `buildMemoryEntryRow`, `buildMemoryEditForm`, `renderRagSearchPopover`, `buildRagQuotesBlock` / `buildRagSourcesBlock` / `buildRagDetailsBlock`). Where the code uses Tailwind steps that are not on the 8-point scale (`p-3` = 12px, `gap-1.5`, `py-0.5`), they are inherited exceptions, not new ones.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla JS + Tailwind CDN; shadcn is not applicable per CLAUDE.md hard constraints: no npm, no bundler) |
| Preset | not applicable |
| Component library | none (hand-built DOM via `document.createElement` / `mcpEl`) |
| Icon library | none (Unicode glyphs only: `▸`, `×`, `⚙`, `✓`, `≈`, `✗`, `↷`) |
| Font | Tailwind default sans stack (no custom font is declared in `index.html`); `font-mono` only for ranks/ids |

Safety rules inherited: all dynamic text through `textContent` (never `innerHTML`); any HTML must go through `DOMPurify.sanitize()`. Task-memory strings (goal, points, constraints) are user text and are rendered with `textContent` only.

| xl | 32px | not used |
| 2xl | 48px | not used |

Exceptions (all inherited from existing blocks, not new):

The new blocks MUST use exactly the same classes as their sibling blocks (see Component Inventory) so no new off-scale value is introduced.
- Touch targets: the `×` per-item button is a compact text control like the existing «Редактировать»/«Удалить» text buttons (no 44px target; desktop-only local app). It must still have a visible focus ring and `aria-label`.

## Color

Palette is the existing dark slate theme. No new color is introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | slate-950 `#020617` (page), slate-900 `#0f172a` (sidebar, `<details>` blocks) | Background, surfaces |
| Secondary (30%) | slate-800 `#1e293b` (item rows, inputs, chips), slate-700 `#334155` (borders) | Task-memory item rows, input fields, borders (`border-slate-700`) |
| Accent (10%) | indigo-500/600/400 (`#6366f1` / `#4f46e5` / `#818cf8`) | see reserved list |
| Destructive | red-400 `#f87171` (text) | per-item `×` hover only («Сбросить» is guarded by `confirm()`, not coloured) |

Text tiers (existing): slate-100/white values, slate-300 labels and goal text, slate-400 secondary item text, slate-500 captions/placeholder labels, slate-600 empty «—».

Accent reserved for (explicit, closed list for this phase):
1. Focus ring on task-memory inputs and buttons (`focus:ring-1/2 focus:ring-indigo-500`).
2. «Сохранить» action in the goal inline edit (`text-indigo-400 hover:text-indigo-300`), same as the long-term edit form.
3. The «новое» marker text on items added in this turn (`text-indigo-400`).

Everything else (labels, item text, `×`, «Сбросить» idle state, «Редактировать») stays in slate tones. «Сбросить» idle: `text-slate-400 hover:text-white` (not red; the destructive step is guarded by the native `confirm()`). Per-item `×`: idle `text-slate-500`, hover `text-red-400`. Emerald/red chip tones belong to Phase 16 quote chips and are not reused here. Extraction-failure marker uses neutral chip `RAG_CHIP_NEUTRAL`, never red (failure is fail-soft, not an error).

## Component Inventory and Layout

### C1. Sidebar block «Память задачи» (D-08, D-10)

- Placement: inside `#memory-panel-body` in `ui/static/index.html`, as a new first child, ABOVE the «Кратковременная (диалог)» row? CONTEXT D-08 says "above «Рабочая (этот чат)»". Decision: insert it between «Кратковременная (диалог)» and «Рабочая (этот чат)». Container id `memory-task-state`, wrapper class `mb-2 hidden` (same `mb-2` as siblings). Shown (class `hidden` removed) only when the active chat has RAG on; hidden otherwise (D-05). Re-rendered by `renderMemoryPanel()` from `state.lastMemory.task_state` and from the `done` frame.
- Header row (same markup as the «Рабочая» header): `flex items-center justify-between mb-1`; left `<span class="text-slate-500">Память задачи</span>` (matches the sibling label style), right: «Сбросить» text button (`text-slate-400 hover:text-white disabled:opacity-50`, built with `buildMemoryButton`, `data-memory-action="task-reset"`). «Сбросить» is hidden when memory is empty.
- Body: three labelled parts stacked with `space-y-2`. Each part: label `<div class="text-slate-300 font-semibold">` («Цель», «Уточнено», «Ограничения и термины»), then content.
  - «Цель»: one row `rounded-lg bg-slate-800 px-2 py-1` with `text-slate-400` text (wrapping allowed, NOT truncated — a goal is short and must be fully readable; use `break-words`), plus «Редактировать» text button (same classes as long-term rows). Edit mode: one `<textarea rows="2" maxlength="300">` with the exact `fieldClass` from `buildMemoryEditForm` (`w-full min-w-0 rounded bg-slate-900 border border-slate-700 px-2 py-1 text-xs text-slate-200 focus:outline-none focus:ring-1 focus:ring-indigo-500 resize-y`) and «Сохранить» / «Отмена» buttons using the same classes and `buildMemoryButton`. Enter does not submit (textarea); Escape cancels. Focus preserved across re-render via the existing `captureMemoryFocus`/`restoreMemoryFocus` pattern (use `data-memory-field="task-goal"`).
  - «Уточнено» and «Ограничения и термины»: list of rows `rounded-lg bg-slate-800 px-2 py-1 flex items-start justify-between gap-2`; text `text-slate-400 break-words min-w-0`; trailing `×` button (`text-slate-500 hover:text-red-400`, `aria-label="Удалить пункт: <text>"`, `title="Удалить пункт"`). Deleting a single item has NO confirm (low-cost, matches inline-edit speed); «Сбросить» has confirm.
- Empty states per part: `<div class="text-slate-600">—</div>` (same as `renderMemoryEntries`). Whole-block empty (new RAG chat, no turn yet): show the three labels with «—» under each plus caption below (see Copywriting).
- Max height: panel already has `max-h-72 overflow-y-auto`; the new block adds no own scroll. Lists are capped server-side (D-03), so no virtualisation.
- Working-memory list (`#memory-working`): the reserved task-state row MUST be excluded server-side from `working` (and from the count `memory-working-count`) per D-08; the UI must not filter it by key name.
- Pending/disabled: while a mutation request is in flight the clicked button gets `disabled` + `opacity-50` (existing `disabled:opacity-50` pattern); no spinner.

### C2. Per-message collapsed snapshot (D-09)

- Rendered only under assistant messages of RAG chats that have a stored snapshot, placed in the same stack as `Цитаты`, `Источники`, `Детали поиска` (after «Детали поиска», wrapped the same way via `wrapToolCard`), as a builder `buildTaskMemoryBlock(rag.task_memory)` next to `buildRagDetailsBlock`.
- Markup: `<details class="rag-task-memory rounded-lg border border-slate-700 bg-slate-900 text-xs text-slate-300 px-3 py-2 mt-2 max-w-[75%]">` — identical class string to `rag-details`. COLLAPSED by default (no `open`). `<summary>` identical class to siblings: `cursor-pointer select-none font-semibold focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-indigo-500`, text `Память задачи` plus a count suffix ` (N)` where N = total items (goal counts as 1 if set), and ` · новое: K` appended when K > 0.
- Body: `mt-2 space-y-2`; reuse `buildRagDetailRow(label, valueNode)` for «Цель:» (one row) and use the same row helper for «Уточнено:» / «Ограничения и термины:» whose value is a vertical list (`space-y-1`) of item spans. Items added in this turn get a trailing `<span class="text-indigo-400 font-semibold">новое</span>` (separated by a space). Read-only: no `×`, no edit (manual control lives only in the sidebar).
- If goal is unchanged from the previous turn it is not marked «новое»; a replaced goal is marked «новое».
- If the snapshot is absent (old messages, non-RAG chats, extraction failed on that turn with no prior memory) the block is not rendered. If extraction failed on that turn but a prior memory exists, the block renders the carried-over snapshot and appends a neutral chip (`RAG_CHIP_NEUTRAL`) `память не обновлена` with `title="Не удалось обновить память задачи на этом ходу; сохранено прежнее состояние"`.

### C3. «Ходов истории» setting (D-13)

- Added to the «Поиск ⚙» popover (`#rag-search-popover`), directly after the «Порог» row and its reset row, before the «Строгий режим» switch (so it sits next to «Кандидатов»/«Порог», as decided). Row markup identical to the «Кандидатов» row: `<div class="flex items-center justify-between gap-2 text-xs text-slate-300"><label for="rag-history-turns" title="…">Ходов истории</label><input id="rag-history-turns" type="number" min="0" max="10" step="1" value="3" class="w-20 rounded-lg bg-slate-800 border border-slate-700 px-2 py-1.5 text-sm focus:outline-none focus:ring-2 focus:ring-indigo-500"></div>`.
- `title` (tooltip): «Сколько последних пар «вопрос–ответ» видит поиск при уточнении запроса (0–10). 0 — только память задачи.»
- Behaviour: saved through the same `PUT /api/v1/chats/{id}/rag` path as «Кандидатов» (same debounce/blur-commit as that input); invalid or out-of-range input is clamped on blur to 0..10 and the field shows the clamped value; empty becomes 3. No new popover width (stays `w-72`). No accent colour; no switch.
- Not shown / disabled when the chat has no RAG (popover itself is already inside `#rag-k-wrap` which is hidden without RAG).

### C4. «Детали поиска» additions (D-12, D-14)

- No new component. In `buildRagDetailsBlock`, on a follow-up turn the existing row «Переписан:» is relabelled to «Уточнён:» when the trace says the rewrite was a history-aware condensing (`search.condensed` flag, name at planner's discretion), value is the condensed query text, via the same `buildRagDetailRow`. The first-turn single-turn rewrite keeps «Переписан:».
- In «Этапы:» add a part `история` (same `font-semibold text-slate-200` span as `лексич.`/`LLM`) with ` ×N` appended (N = pairs used), shown only when condensing ran. If the condensed output was rejected and the raw question was used alone, add a skipped row via the existing `Пропущено:` mechanism: `↷ Уточнение запроса: пропущено (ответ модели не подошёл, искали по исходному вопросу)`.
- The «no memory» eval flag has no UI.

### C5. `done` frame handling

- The `done` frame carries the fresh task memory; the client updates `state.lastMemory.task_state` and calls `renderMemoryPanel()` immediately (no extra GET), and attaches the per-message snapshot (with the «новое» diff) to the just-finished assistant message so C2 appears without reload. After regenerate / edit / branch switch the client re-fetches `GET /api/v1/chats/{id}/memory` (existing reload path) so the sidebar reflects the restored memory (D-11).
- Streaming: the block stays at previous values until `done`; no intermediate "updating" skeleton. Between the end of the answer text and `done` (extraction runs inside the turn) the existing "generating" indicator simply lasts a little longer; no new indicator.

## Interaction Contract

| Interaction | Behaviour |
|-------------|-----------|
| Toggle RAG on/off in chat | Block C1 shown/hidden immediately; data is kept server-side (not cleared) when RAG is toggled off |
| Open sidebar «Память» | Block C1 is inside the already-collapsible `#memory-panel-body` (`data-fold-toggle`); no new fold control |
| Edit goal | «Редактировать» → inline textarea; Сохранить → `PUT` goal route; on success re-render from response; on failure toast `error`, draft kept |
| Delete item `×` | Immediate `DELETE`; row disabled during request; on failure toast and row restored |
| «Сбросить» | `confirm()` with the destructive copy below; on OK `POST` reset; then re-render the empty state |
| Branch switch / regenerate / edit earlier message | Sidebar block refreshes to the restored snapshot; if an inline edit draft is open it is discarded (same as `state.editingMemory` cleanup when the entry disappears) |
| Keyboard | All new controls are native `button`/`input`/`textarea`/`summary` (tab-reachable); Escape cancels goal edit; visible focus ring per colour contract |
| Accessibility | Sidebar block wrapper `role="group"` `aria-label="Память задачи"`; item lists use `role="list"`/`role="listitem"`; `×` has per-item `aria-label`; «новое» is text, not colour-only |
| Mutation requests | Origin + JSON content type as in Phase 11 (`apiFetch`), routes user-scoped; errors surface through `showToast(message, 'error')` |

Responsive: no new breakpoints. The sidebar is fixed `w-64`; per-message blocks keep `max-w-[75%]`. Long items wrap with `break-words`; nothing truncates silently except nothing — task-memory text is never truncated (it is the thing the user needs to verify).

## Decisions Recorded (made without asking, per yolo mode)

1. Block position: between «Кратковременная (диалог)» and «Рабочая (этот чат)» inside `#memory-panel-body` (satisfies D-08 "above Рабочая"; keeps the short-term count row first).
2. Roadmap flag «confirm `dialog_state` rendering in the memory panel»: CONFIRMED — the reserved `dialog_state` row is never shown as a plain working row; the API returns it as a separate `task_state` object (goal / clarified[] / constraints[]) and the panel renders it only through C1. The reserved row is excluded from `working` and its count.
3. Goal text is never truncated (unlike working-memory values, which truncate at 160 chars), because goal-keeping is the verifiable claim of the phase.
4. Per-item `×` has no confirm; «Сбросить» has native `confirm()`.
5. Snapshot block is read-only and collapsed by default; the sidebar is the only editing surface.
6. «Ходов истории» is a plain number input (no slider, no switch) with clamp 0..10, default 3, matching «Кандидатов».
7. The extraction failure is a neutral chip, not an error colour, consistent with fail-soft rules (14 D-04, 15 D-14, 17 D-07).
8. Accent colour use is limited to focus rings, the goal «Сохранить» action and the «новое» marker.
9. No new CDN library, no new CSS file; new style hooks use existing Tailwind classes only.
