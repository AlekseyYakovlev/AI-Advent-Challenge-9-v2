<objective>
Build the task-memory foundation: the table, the two settings, the pure document/merge/snapshot code, and the fail-soft extraction call with a staged (uncommitted) update that later plans hook into the chat turn.

Purpose: RCHAT-02 needs a deterministic post-turn update. Everything that decides what enters memory lives here and is unit-tested without a live model.
Output: `agent/task_memory.py`, `ChatTaskMemory`, `ChatRagConfig.history_turns` with its idempotent column, `TASK_MEMORY_ENABLED` / `TASK_MEMORY_TIMEOUT`, a public stage-call wrapper in `agent/rag_llm.py`, a public tag neutraliser in `agent/rag_rank.py`, tests.

Storage choice (CONTEXT "Claude's Discretion"): a dedicated table `ChatTaskMemory`, not a reserved `dialog_state` row of `WorkingMemory`. Reason: a reserved row would leak into three existing places (the "Working memory" JSON line of `build_system_prompt`, the `working` list of `GET /chats/{id}/memory`, and the `save_working_memory` tool, which could overwrite it); each would need special-casing. With a separate table the plain working-memory list and its count are untouched, which is what UI-SPEC and D-08 require. No AI-SPEC exists for this phase (none of Phases 13-16 used one); none is invented here.
</objective>

| stored task memory -> later prompts | stored text is replayed into the system prompt and the condensing prompt by later plans |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-17-02 | Tampering | memory poisoning by model output (law text, the assistant's own answer, invented numbers) | mitigate | `filter_user_stated` (stem overlap >= 0.5 and digit subset against the user message), prompt rule, hostile-output test (D-04) |
