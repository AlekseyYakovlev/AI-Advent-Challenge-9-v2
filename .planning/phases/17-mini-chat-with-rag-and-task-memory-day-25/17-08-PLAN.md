<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model answers and user text -> judge prompt | untrusted text is sent to the DeepSeek judge |
| raw run data -> rendered report tables | model output is written into markdown and CSV |
| local machine -> DeepSeek API | answers and questions leave the machine when the judge runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-38 | Tampering | prompt injection of the judge through answer or memory text | mitigate | every field passes `_neutralise` and sits in its own tag; system prompt states tag content is data; test with closing tags in the answer |
| T-17-39 | Repudiation | failed, gated or error turns left out of tables, or a judge verdict lost on re-render | mitigate | renderers never drop a turn (tests); existing judge columns are carried over on re-render |
| T-17-40 | Tampering | markdown table broken or CSV formula injection by model output | mitigate | `_cell` escaping for markdown; CSV written with the `csv` module as in Day 24; outputs are local evaluation files opened by their author |
| T-17-41 | Information disclosure | API key in `judge_meta.json` or console output | mitigate | meta holds model, base URL, counts and timestamp only (as on Day 24); test asserts the key string is absent from the meta |
| T-17-42 | Information disclosure | scenario text sent to DeepSeek | accept | scenarios are invented cases on public law texts; same disposition as the Day 23 and Day 24 judge runs |
| T-17-SC | Tampering | package installs | accept | this plan installs no package |
</threat_model>
