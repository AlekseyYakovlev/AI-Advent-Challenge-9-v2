<interfaces>
Fixture format (binding for plans 17-05, 17-08, 17-09, 17-10):

Top level: `version` (1), `status` (`"draft"` or `"frozen"`), `frozen_at` (ISO date string, null while draft), `corpus` (`["ФЗ-196", "КоАП РФ"]`), `scenarios` (array of exactly two).

Scenario: `id` (`"A"` or `"B"`), `title` (Russian), `goal` (one Russian sentence: what the user wants from the whole dialog; shown to the judge), `goal_keywords` (array of lowercase word stems expected in the stored goal text), `turns` (array of 10 to 15).

Turn: `id` (`"A01"` … / `"B01"` …, ordered), `text` (the user message, Russian), `kind` (one of `direct`, `followup`, `out_of_corpus`, `goal_check`), `expect_memory` (object with optional arrays `goal`, `clarified`, `constraints`; each entry is a lowercase substring that must be found in that part of the task-memory snapshot after this turn; empty object when nothing is expected), `expect_article` (string such as `"12.9"` or null; the article number that must appear in the sources of this turn; set only on marked follow-ups and on direct questions where one article is the answer), `expect_keywords` (array of lowercase substrings expected in the answer text; empty array allowed).

Envelope analog: tests/fixtures/rag/control_set.json (`version`, `status`, `frozen_at`, `corpus`).
Knowledge base for the runs: `eval_out/day23/eval.db` + `eval_out/day23/eval_kb`, KB id 2 (`day22-bge`, bge-m3). Chunk sections in that database tell which articles the corpus really contains.
