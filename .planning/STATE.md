## Accumulated Context

### Decisions

- Auth is pulled out as its own foundation phase/branch (`Auth`, not `DayN`) because every later table needs `user_id` scoping from creation — retrofitting later would touch every table's FK design.
- Tool-call dispatcher (`agent/tools.py`) is built once in Phase 2 (Memory) and reused unchanged by Phases 3-5 (Personalization, Tasks, Invariants). Do not rebuild it.
- Branch naming: `Auth`, `Day11`, `Day12`, `Day13`, `Day14`, `Day15` — one branch per phase, pushed and merged to `main`, never deleted (per PROJECT.md Constraints).
- Memory/task/invariant writes must be synchronous, per-chat-locked, and tool-call-only — never fire-and-forget/debounced like the existing `extract_and_update_facts` pattern (documented pitfall: implicit-classification relabeling).
- Multiple tool calls in one LLM turn execute strictly sequentially, never `asyncio.gather`d — later calls may depend on IDs generated by earlier calls in the same turn.
- TRANS-01/02/03 hard enforcement is deliberately deferred to Phase 6; Phases 4-5 build the state enum, transition history, and invariant conflict machinery that Phase 6 hardens.
