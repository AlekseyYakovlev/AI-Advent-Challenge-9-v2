## Problem
Chat already has a tool-call loop (agent/ws.py -> build_tool_schemas()/dispatch_tool_calls() in agent/tools.py,
OpenAI-format tools passed to agent/llm_client.py stream_chat with tools=). Phase 7 built agent/mcp_client.py with a
per-(user_id, server_id) persistent session registry (get_live_session / is_connected). Today the chat never sees MCP
tools, so the model answers "У меня нет доступа к инструментам файловой системы" (user prompts:
"используй инструмент list_allowed_directories").

## Required behavior
1. When building tools for a chat turn, add the tools of the CURRENT USER's currently-connected + enabled MCP servers
   (from the live session registry; tool list cached from the connect result or list_tools) to the existing built-in tool
   schemas. Servers not connected contribute nothing. Never expose another user's sessions.
2. Namespace MCP tool names to avoid collisions with built-ins/other servers, valid for OpenAI function names
   ([a-zA-Z0-9_-], <=64 chars), e.g. mcp__<server-slug>__<tool>; map back to (server_id, tool) at dispatch. Preserve
   inputSchema as parameters (clean like existing _clean_schema).
3. Dispatch: route namespaced calls to ClientSession.call_tool on the live session; return text content (and isError) as
   the role="tool" message; failures (server disconnected mid-turn, timeout, invalid args, is_error) become tool results
   the model can see, never crash the WS turn or the Agent. Keep the existing strict-sequential execution of multiple tool
   calls and the existing loop/iteration limits. Apply a per-call timeout (new setting in shared/config.py, default e.g.
   30s) and cap result size sent back to the model.
4. Works for both backends (DeepSeek and LM Studio) through the same path as existing tools. Do not regress existing
   memory/task/invariant tools or the no-tools path when no MCP server is connected.
5. UI: in the chat, show that a tool was called (tool name, arguments, result/error, collapsed by default), rendered with
   textContent/DOMPurify only (no raw innerHTML). Follow existing WS event conventions in agent/ws.py + ui/static/app.js
   (vanilla JS, CDN libs only; app.js and index.html use CRLF line endings - preserve them).
6. Logging via structlog (no secrets/env values, no full tool output at info level), type hints, async everywhere,
   project conventions in CLAUDE.md.
7. Tests (pytest, respx / existing fixture server tests/fixtures/mcp_stdio_server.py): schema building with/without
   connected servers, name mapping and collision safety, dispatch success, tool isError, server disconnected mid-turn,
   timeout, cross-user isolation, and an end-to-end WS chat turn where a mocked LLM emits an MCP tool call and receives
   the result. Also verify against the real filesystem.exe (C:\Users\Aleksey\go\bin\filesystem.exe, allowed dir
   C:\Projects\AiAdventAgentV2) with a Playwright run on an ISOLATED instance (scratch DB_PATH env var; NEVER use the

   8000/8001 must be free before starting — run.py kills python processes on them). Playwright (python, chromium) is
