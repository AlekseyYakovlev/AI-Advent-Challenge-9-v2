### WR-03 — open_session leaks owner task + child process on CancelledError
Apply the review's fix in agent/mcp_client.py `open_session`: on `asyncio.CancelledError` while awaiting `handle.ready`, cancel the
owner task, await it (suppressing CancelledError/Exception), close `handle.errfile`, re-raise. Test: cancel a task that is inside
open_session against the `hang` fixture mode and assert the fixture child process is gone and nothing is registered in `_sessions`.

### WR-05 — get_status mutates the registry without the per-server lock
In `get_status`, take `_lock_for(key)` for the dead-handle branch only; after acquiring it re-check `_sessions.get(key) is handle`
and write `_last_results` only if that still holds (a concurrent disconnect/connect must win). In `cleanup_server`, pop the lock
from `_locks` while still holding it. Do NOT hold the lock on the healthy fast path (Settings polling must not block on a connect).
Tests: interleaving cases from the review (disconnect during a dead-handle status check leaves NOT_CONNECTED, no stale PROCESS_EXITED
after a successful reconnect).

### WR-06 — 2s ping timeout kills healthy busy servers
Change `_is_alive` semantics: only a finished owner task, a closed handle, or a broken-stream/closed-resource style error means
DEAD. A ping TIMEOUT means "unresponsive": keep the session and report it as still connected (log a debug/warning with ids only).
Also make `list_mcp_servers` in agent/main.py ping servers CONCURRENTLY (`asyncio.gather`, per-server exceptions must not fail the
list). Tests: a `slow` fixture-mode server that answers pings late is NOT killed; a truly dead process (owner task finished) is
still reported PROCESS_EXITED; N unresponsive servers cost ~1 timeout, not N. Keep `ensure_connected` (auto-connect) consistent with
the new semantics and keep its tests green.

### WR-08 — misleading error classification + unbounded stderr temp file
(a) In `classify_mcp_error` stop mapping every OSError to COMMAND_NOT_FOUND: FileNotFoundError of the COMMAND stays
COMMAND_NOT_FOUND; other OSErrors (bad/nonexistent `cwd`, PermissionError, "not a valid Win32 application") must produce an accurate

seconds. If the test PASSES: the finding is mitigated by the SDK — add a short note to docs/ARCHITECTURE.md explaining that
