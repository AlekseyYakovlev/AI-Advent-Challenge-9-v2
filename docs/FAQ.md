# FAQ: частые проблемы и их решения

Этот файл для тех, кто пользуется приложением и столкнулся с ошибкой. Каждый раздел описывает одну проблему: в заголовке симптом и точный текст ошибки, затем причина и шаги решения. Названия настроек (`BIND_HOST`, `LOGIN_MAX_FAILED_ATTEMPTS` и другие) задаются в файле `.env`; после их изменения приложение нужно перезапустить.

## Не удаётся войти: «Неверное имя пользователя или пароль» (401)

Причина: имя пользователя или пароль не совпали с сохранёнными. Сервер намеренно не уточняет, что именно неверно.

Что сделать:
1. Проверьте раскладку клавиатуры, регистр и Caps Lock.
2. Введите имя и пароль заново.
3. Не повторяйте вход много раз подряд: серия неудачных попыток приводит к временной блокировке (см. следующий раздел).

## Вход заблокирован: «Слишком много неудачных попыток входа. Повторите позже» (429)

Причина: сработала защита от подбора пароля. Неудачные попытки считаются отдельно для пары «имя пользователя плюс адрес клиента». По умолчанию допускается 5 неудачных попыток (`LOGIN_MAX_FAILED_ATTEMPTS`), после этого вход блокируется на 300 секунд (`LOGIN_LOCKOUT_SECONDS`).

Что сделать:
1. Подождите время, указанное в заголовке ответа `Retry-After`, и войдите снова с правильным паролем.
2. Если пределы слишком строгие, администратор может изменить `LOGIN_MAX_FAILED_ATTEMPTS` и `LOGIN_LOCKOUT_SECONDS` в `.env` и перезапустить приложение.

## После входа снова просит войти: «Not authenticated» (401)

Причина: сервер не нашёл действующую сессию. Сессия хранится в HttpOnly-куке `session_id` и живёт 30 дней. Ошибка появляется, если срок сессии истёк, кука удалена, или браузер блокирует куки для адреса приложения (например, в приватном режиме или при строгих настройках приватности).

Что сделать:
1. Войдите снова.
2. Разрешите куки для адреса, по которому вы открываете приложение.
3. Не переключайтесь между адресами `localhost` и `127.0.0.1`: для браузера это разные сайты, и кука одного не видна другому.

## Вход с другого компьютера в локальной сети: «Cross-origin request rejected» (403)

Причина: по умолчанию приложение доступно только на этом компьютере. Чтобы открыть его с другого устройства, нужен режим локальной сети: `BIND_HOST=0.0.0.0` в `.env` на компьютере с приложением. Кроме того, сервер проверяет заголовок `Origin` запроса. Он принимается, если это `http://localhost` или `http://127.0.0.1` на порту `UI_PORT`, либо если хост в `Origin` совпадает с хостом из заголовка `Host`, схема `http` и порт равен `UI_PORT` (по умолчанию 8000). Запросы с других сайтов и с другим портом отклоняются.

Что сделать:
1. Установите `BIND_HOST=0.0.0.0` и перезапустите приложение.
2. Откройте приложение с другого устройства по адресу из списка, который печатается при запуске, например `http://адрес-компьютера:8000`, с портом `UI_PORT`.
3. Не открывайте приложение через прокси или по другому порту: `Origin` перестанет совпадать с `Host`.

## Запрос с API-ключом: «Invalid or revoked API key» (401)

Причина: ключ передан неверно, введён с ошибкой или отозван. Ключ отправляется в заголовке `Authorization: Bearer <ключ>`; ключи начинаются с префикса `aia_`. Если заголовок есть, решает только он: при неверном ключе кука сессии не используется как запасной вариант, а ответ содержит `WWW-Authenticate: Bearer`. Часть операций доступна только из веб-интерфейса по сессии, по API-ключу они возвращают 403 («Эта операция доступна только из веб-интерфейса (по сессии), а не по API-ключу»).

Что сделать:
1. Проверьте, что заголовок написан как `Authorization: Bearer aia_…` без лишних пробелов и кавычек.
2. В веб-интерфейсе проверьте, что ключ не отозван; при необходимости создайте новый.
3. Для операций «только по сессии» войдите в веб-интерфейс.

## Модель не отвечает: «LM Studio is not running» (503)

Причина: выбран локальный провайдер LM Studio, но приложение не может подключиться к нему по адресу `LM_STUDIO_BASE_URL` (по умолчанию `http://localhost:1234`). HTTP-эндпоинт чата в этом случае отвечает кодом 503 с кодом ошибки `LM_STUDIO_UNAVAILABLE`.

Что сделать:
1. Запустите LM Studio и включите локальный сервер.
2. Загрузите нужную модель.
3. Проверьте, что `LM_STUDIO_BASE_URL` указывает на правильный адрес и порт, либо переключите провайдера на DeepSeek в настройках.

## MCP сервер не подключается

Причина: процесс MCP сервера не запустился или завершился с ошибкой. Для запуска используются команда, аргументы и рабочая папка из настроек сервера.

Что сделать:
1. Откройте раздел «MCP серверы» и прочитайте последние строки stderr, которые показаны под сервером: там обычно причина.
2. Проверьте команду, аргументы (каждый на отдельной строке) и рабочую папку.
3. Для Python-серверов должен быть установлен пакет `mcp`.
4. Учтите, что результат инструмента длиннее 20000 символов (`MCP_TOOL_RESULT_MAX_CHARS`) обрезается.

## Слишком частые сообщения: «Rate limit exceeded» (429)

Причина: для каждого чата действует ограничение на частоту сообщений: по умолчанию 30 сообщений в минуту (`RATE_LIMIT_MESSAGES_PER_MINUTE`).

Что сделать:
1. Подождите несколько секунд и отправьте сообщение снова.
2. Если лимит мешает, администратор может изменить `RATE_LIMIT_MESSAGES_PER_MINUTE` в `.env` и перезапустить приложение.

## Чат занят: ответ ещё генерируется (409)

Причина: в этом чате ещё идёт обработка предыдущего запроса. HTTP-эндпоинт чата отвечает кодом 409 и текстом «Chat is busy with another request; retry when the current turn has finished».

Что сделать:
1. Дождитесь окончания текущего ответа.
2. Повторите запрос.
