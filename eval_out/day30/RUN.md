# Day 30 — живой прогон со второй машины: что сделать

Сервер — Windows-машина с приложением. Вторая машина — Mac (Python 3.14.7). Скрипт проверки — один файл `scripts/verify_service.py` (только стандартная библиотека). Ключ в этот файл не записывается.

SHA-256 текущего `scripts/verify_service.py`:

```
a7687538d9a7801533aa8f8cbb8f5d39ed11300a7da8a473db482e01b157e1d2
```

LAN-адреса сервера, найденные `shared.network.lan_ipv4_addresses()`: `192.168.88.224`, `10.8.1.1` (для Mac, скорее всего, нужен первый; точный адрес также печатает `run.py` и показывает Настройки -> «Сеть»).

## Шаги

1. На сервере (Windows) в `.env` поставьте:

   ```
   BIND_HOST=0.0.0.0
   RATE_LIMIT_MESSAGES_PER_MINUTE=5
   MAX_CONCURRENT_GENERATIONS=2
   ```

   `RATE_LIMIT_MESSAGES_PER_MINUTE=5` — намеренно сниженное значение для демонстрации (по умолчанию 30). Настройки входа (`LOGIN_MAX_FAILED_ATTEMPTS`, `LOGIN_LOCKOUT_SECONDS`) оставьте по умолчанию. Затем перезапустите `python run.py` (без перезапуска значения не применятся) и убедитесь, что в консоли напечатаны LAN-адреса.

2. Правило Windows Firewall для портов 8000 и 8001 должно быть на месте (раздел «Windows Firewall» в `docs/USER_GUIDE.md`; оно нужно было и для проверки интерфейса).

3. В LM Studio загрузите модель, которая будет отвечать, и запишите её название.

4. В браузере: Настройки -> «API ключи» -> «+ Создать ключ». Скопируйте ключ (показывается один раз).

5. Скопируйте на Mac один файл `scripts/verify_service.py` (без репозитория, venv и `pip install`). Сверьте хеш:

   ```
   shasum -a 256 verify_service.py
   ```

6. На Mac:

   ```
   export AIA_API_KEY='<ключ>'
   python3 verify_service.py --url http://<LAN-адрес сервера>:8001 --n 6 --rate-mode both --server-rate-limit 5 --server-max-concurrent 2 --out day30_run
   ```

   Вместо переменной окружения можно передать `--key aia_...`. Режим по умолчанию `--rate-mode chat` — это простая демонстрация «короткие сообщения до 429»; `both` дополнительно запускает быстрый вариант (`fast`), который показывает лимит, даже если модель слишком медленная, чтобы ответить на пять сообщений за минуту. Необязательно: `--keep` оставит чаты скрипта, чтобы показать их в браузере; чтобы сохранить вывод консоли, добавьте в конец команды `2>&1 | tee day30_run/console.txt` (каталог `day30_run` должен существовать заранее: `mkdir -p day30_run`).

7. Коды выхода: 0 — всё как ожидалось; 1 — какое-то ожидание не выполнено; 2 — не прошла предварительная проверка (адрес, ключ, недоступность). Код 1 с пометкой «limit not reached» в режиме `chat` при медленной модели — допустимый результат, он будет записан в отчёт как есть.

8. Принесите в репозиторий в папку `eval_out/day30/`: `verify_results.md` и `verify_results.json` (обязательно), `console.txt` (по желанию).

9. После прогона на сервере: верните `RATE_LIMIT_MESSAGES_PER_MINUTE` (удалите строку или поставьте 30), перезапустите `python run.py` и отзовите ключ в Настройках, если он больше не нужен.

10. Когда закончите, напишите «готово», либо какая часть не запускалась. В отчёт попадёт только то, что есть в принесённых файлах и в вашем сообщении.
