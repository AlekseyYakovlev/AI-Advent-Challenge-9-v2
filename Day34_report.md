# Day 34 — Ассистент по файлам проекта: отчёт

## Задание

Задание дня 34: ассистент по файлам проекта. Пользователь формулирует цель обычным сообщением в чате, а ассистент сам читает файлы, ищет по коду, анализирует, создаёт и меняет файлы, показывает diff и перечисляет изменённые файлы. Результат должен быть воспроизводимым: цель, коммит, модель и инструменты записаны в журнал.

Все прогоны ниже сделаны на локальной модели `qwen/qwen3.5-9b` (LM Studio), на коммите `2958292`, запись в копию репозитория, а не в рабочую папку проекта.

## Что построено

- Инструменты чтения `read_file`, `search_text`, `find_usages` и инструменты записи `write_file`, `edit_file` в `mcp_servers/project_git.py`.
- Флаг `--allow-write` и вторая запись сервера `project-files`; `local-git` и `/help` остаются только на чтение.
- Правила записи: нельзя писать вне корня, в `.git`, в `.env*`, в игнорируемые файлы, в имена устройств, в бинарные файлы и файлы больше 200 000 байт.
- Цветная карточка diff в чате (добавленные, удалённые строки, заголовки, итог `+A −R`).
- Скрипты `scripts/files_task.py` (одна цель, журнал и патч), `scripts/files_eval.py` (четыре сценария на изолированной копии приложения), `scripts/e2e_project_files_playwright.py` (проверка в браузере).
- Тесты: `tests/test_mcp_project_files.py`, `tests/test_files_task.py`, `tests/test_files_eval.py`, `tests/test_diff_card_ui.py`, `tests/test_mcp_project_git.py`, `tests/test_tool_guard.py`.

## Как это работает

1. Цель приходит как обычное сообщение в чат, без отдельной команды.
2. Работает существующий цикл инструментов: не больше `MAX_TOOL_ROUNDS = 15` раундов вызовов за один ответ.
3. Модель вызывает инструменты сервера `project-files`: читает, ищет, смотрит историю git.
4. Запись (`write_file`, `edit_file`) сохраняет файл сразу и возвращает diff.
5. В чате появляется карточка вызова; для записи в ней виден diff.
6. В конце ответа модель перечисляет изменённые файлы; откат делается средствами git.

### usages

Цель: «Найди все места в проекте, где используется функция cleanup_chat_caches, и объясни роль каждого места. Файлы не меняй.»

Вызовы по порядку:

- `find_usages` — 6 использований в 4 файлах (определение 1, импорт 2, вызов 3).
- `read_file` `agent/main.py` (весь файл), затем `agent/main.py` строки 720–740.
- `read_file` `agent/state.py`.
- `read_file` `tests/test_limits_core.py` строки 100–120.
- `read_file` `tests/test_titles.py` строки 15–25 и 430–450.

Фрагмент ответа:

> Найдено **6 мест использования** функции `cleanup_chat_caches` в **4 файлах**.
> **agent/main.py:726** — вызов при удалении чата. Вызов функции сразу после удаления записи о чате из базы данных. Это гарантирует, что все связанные с этим чатом данные в памяти будут очищены: активные потоки, ограничители скорости WebSocket, замок синхронизации, задача автозаголовка.
> Итог: функция используется для очистки всех данных в памяти, связанных с чатом, чтобы избежать утечек после удаления чата.

Патч пустой, как и требовалось. Оценка: ответ по существу верный (импорт, вызов при удалении чата, определение в `agent/state.py`, два тестовых вызова), но проверка `mentions_usage_files` не пройдена: в ответе не все ожидаемые пути записаны в той форме, которую ищет проверка (в ответе `tests/...` встречается как имя файла `test_limits_core.py`, `test_titles.py`). Это упрощённая строковая проверка, поэтому «нет» здесь означает «не подтверждено автоматически», а не доказанную ошибку.

## Как повторить

Четыре сценария целиком (нужны LM Studio с загруженной чат-моделью и свободные порты 18000/18001):

```
python scripts/files_eval.py check
python scripts/files_eval.py run
python scripts/files_eval.py summary
```

Одна цель:

```
python scripts/files_task.py --root <клон> --goal "..." --out <папка>
```

с переменной `FILES_TASK_API_KEY`. Повтор означает тот же коммит, ту же цель и температуру 0; модель при этом не обязана дать побайтно тот же ответ.

## Ограничения

- Превью вызовов в карточках и журналах обрезано до 4 000 символов; патч приводится полностью.
- Карточки вызовов хранятся только в сессии браузера: переключение чата их сохраняет, полная перезагрузка страницы — нет.
- `git_recent_commits` показывает не больше 50 коммитов за вызов.
- Не включайте `local-git` и `project-files` одновременно для этого ассистента: инструменты чтения дублируются, и модель путается в выборе.
- Наблюдено в прогонах: небольшая локальная модель `qwen/qwen3.5-9b` в двух из трёх сценариев создания файла (changelog, readme) остановилась до записи файла, в третьем (adr) не перечислила файл в ответе. Лимит раундов тут не причина.
- Автоматические проверки грубые (поиск строк в ответе и патче); оценка содержания сделана вручную в разделах сценариев.
