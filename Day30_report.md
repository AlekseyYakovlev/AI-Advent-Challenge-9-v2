# Day 30 — локальная LLM как приватный сервис: отчёт

## Постановка

Цель: приложение отдаёт локальную модель в домашнюю сеть как приватный сервис: режим LAN, API-ключи, HTTP-чат и лимиты. Этот отчёт фиксирует проверку со второй машины в той же сети: одиночный файл `verify_service.py` запускается на Mac и ходит на сервер, работающий на Windows.

- Сервер: компьютер с Windows, приложение запущено через `python run.py`, адрес Agent в прогоне — `http://192.168.88.224:8001`.
- Клиент: Mac, Python 3.14.7, платформа `macOS-26.6.2-arm64-arm-64bit-Mach-O` (из [verify_results.json](eval_out/day30/verify_results.json)). Скрипт запущен из каталога `Downloads` на Mac (путь виден в [console.txt](eval_out/day30/console.txt)).
- Провайдер и модель (из JSON): LM Studio, `qwen/qwen3.5-9b`.
- Лимиты на время прогона (значения «справочно» переданы скрипту флагами, сервер их скрипту не сообщает): `RATE_LIMIT_MESSAGES_PER_MINUTE=5` и `MAX_CONCURRENT_GENERATIONS=2`. Лимит сообщений 5 в минуту на чат **нарочно занижен для демонстрации**, чтобы 429 появился за несколько запросов; значение по умолчанию — 30. Блокировка входа осталась по умолчанию: `LOGIN_MAX_FAILED_ATTEMPTS=5`, `LOGIN_LOCKOUT_SECONDS=300`.
- Режимы проверки лимита: оба, `--rate-mode both` — `chat` (короткие сообщения подряд до 429) и `fast` (быстрый вариант на повторяющемся запросе с переполнением контекста, который показывает лимит, даже если модель медленная).
- Команда (ключ передан через переменную окружения `AIA_API_KEY`, сам ключ в отчёт не попадает; в консоли записана команда с путём файла на Mac):

  ```
  export AIA_API_KEY='<ключ>'
  python3 verify_service.py --url http://192.168.88.224:8001 --n 6 --rate-mode both --server-rate-limit 5 --server-max-concurrent 2 --out day30_run
  ```

- Префикс ключа в файлах результатов: `aia_mD7z`.
- SHA-256 скрипта в JSON: `a7687538d9a7801533aa8f8cbb8f5d39ed11300a7da8a473db482e01b157e1d2`; он совпадает с SHA-256 текущего `scripts/verify_service.py` в репозитории.
- Начало прогона: 2026-10-12T18:56:13 UTC; окончание: 2026-10-12T18:56:36 UTC (из файла результатов).
- Коммит кода репозитория на момент написания отчёта: `a27ddfb`. Каким именно коммитом собран сервер на Windows во время прогона, в файлах результатов не записано.
- Файлы результатов: [verify_results.md](eval_out/day30/verify_results.md), [verify_results.json](eval_out/day30/verify_results.json), [console.txt](eval_out/day30/console.txt). Памятка для прогона: [RUN.md](eval_out/day30/RUN.md).

Главный результат, коротко: все пять групп проверок со второй машины дали ожидаемый результат, код завершения скрипта 0. Сервер ответил на `/health` без ключа за 0.02 с, принял ключ и ответил 401 на неверный. Шесть параллельных запросов при лимите 2 одновременных генераций завершились без ошибок, четыре из них ждали в очереди (от 2.75 до 4.56 с). Лимит сообщений дал 429 на 6-м запросе в обоих режимах с `Retry-After` 46. Переполнение контекста вернуло 413 `CONTEXT_OVERFLOW` с предложением стратегии `sliding`; все 8 созданных скриптом чатов удалены.

## Что проверено автоматически

Тесты этой фазы (в `tests/`):

- `test_limits_config.py` — значения по умолчанию и проверка настроек лимитов;
- `test_limits_core.py` — модульные тесты примитивов лимитов в памяти;
- `test_rate_limit.py` — общий лимит сообщений на чат для WebSocket и HTTP-чата;
- `test_generation_queue.py` — ограничение числа генераций и очередь ходов чата;
- `test_login_lockout.py` — блокировка входа после неудачных попыток;
- `test_limits_ui.py` — проверка исходников: сообщения о лимитах в чате и на форме входа;
- `test_verify_service.py` — скрипт проверки против локального сервера-заглушки на loopback;
- `test_docs_day30.py` — привязка документации к коду и к существующим файлам тестов.

Полный набор `python -m pytest tests/ -q`, последний запуск при написании отчёта: `2572 passed, 11 skipped, 14 warnings in 472.90s`.

## Ограничения

- Лимиты и счётчики живут в памяти процесса Agent и сбрасываются перезапуском.
- Лимит сообщений считается на чат, а не на пользователя или ключ.
- Блокировка входа считается по паре имя пользователя и адрес клиента.
- У очереди генераций нет ограничения по длине и по времени ожидания.
- Трафик идёт по обычному HTTP: ключ ходит по домашней сети открытым текстом; ключ отзывается в настройках после прогона.
- Лимит 5 сообщений в минуту занижен нарочно для демонстрации; значение по умолчанию 30.
- Один прогон, одна модель, одна сеть; время ответов зависит от модели и железа. Режим `chat` зависит от скорости модели: при медленной модели лимит может не достигнуться за минуту (здесь он достигнут за 14.0 с).
- Значения лимитов в файлах результатов справочные: их скрипту передал пользователь флагами, сервер их не сообщал.
- Ручная проверка интерфейса с другого устройства (VER-05) подтверждена словами пользователя без подробностей.
